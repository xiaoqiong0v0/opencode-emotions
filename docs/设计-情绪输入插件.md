> **v0.x 是本文档的修订号**（v0.1 → v0.2 → v0.3），**不是 npm 包版本**；包版本以 `package.json` 的 `version` 为准。

> 变更说明（原：符号解析 → 现在：移除，仅命令；为什么）：`docs/changes/设计-情绪输入插件.20261014.md`

## 1. 背景与目标

模型看不到用户的表情/情绪，容易误读语气。本插件给用户一个**极短、无歧义**的输入通道表达当前情绪，并把简写**归一化为可见的情绪标注**写回消息，让模型读到准确的情绪信息。

设计原则：
- 输入极短、直觉（英文命令）
- 输出**零自然语言**（`emoji(等级/3)`），天然免 i18n、跨模型自解释
- 无状态，只作用于**当前这条消息**

## 2. 输入方式：情绪命令（英文、带参数）

- 例：`/angry 需求又改了` → `😡(2/3) 需求又改了`
- 由插件通过 `config` 钩子注册；每个命令绑定固定「情绪 + 等级」
- 无参数时只产生标注本身
- 占位符用 **`$ARGUMENTS`**（实测有效；`{{input}}` 无效）

**命令集**

| 命令 | 标注 |
|---|---|
| `/annoyed` | 😠(1/3) |
| `/angry` | 😡(2/3) |
| `/furious` | 🤬(3/3) |
| `/confused` | 🤔(2/3) |
| `/speechless` | 😑(2/3) |
| `/neutral` | 😐 |
| `/ok` | 🙂(1/3) |
| `/happy` | 😊(2/3) |
| `/great` | 🤩(3/3) |

> 固定枚举，可增删；只注册精准主命令，不设别名（命令面板保持精简）。

### 2.1 为什么移除符号解析（`!` / `?` / `...` / `。。。` / `666`）

符号（前缀/后缀标点与数字串）曾是 v0.2 的手动入口，现已**从实现中删除**：

- **冗余**：语音来源（见 `docs/设计-语音输入注入.md`）已能自动产出同一套 `emoji(等级/3)` 标注，手动符号是第二条通往同一结果的路径。
- **有误伤**：`? 这是什么`（疑问句）、`666 元`（数字）等无法与「有意表达情绪」100% 区分，token 规则只能收窄、不能消除。
- **有硬限制**：行首半角 `!` 被 opencode shell 模式拦截、到不了插件；靠「请用全角 `！`」这类约定绕行，体验割裂。
- **命令已够用**：命令显式、零歧义、可枚举，且能承载固定「情绪 + 等级」，是更可控的手动兜底。

结论：**只保留命令**。同一情绪模型层（`src/lib/emotions.ts`）不变，未来新增来源仍归一到 `emoji(等级/3)`。

## 3. 归一化输出

- 统一格式 **`emoji(等级/3)`**，不含任何自然语言
- 中性（`/neutral`）只输出 `😐`，不带等级
- 标注统一置于消息**最前面**

**示例**

| 输入 | 归一化后 |
|---|---|
| `/angry 需求又改了` | `😡(2/3) 需求又改了` |
| `/happy 测试通过` | `😊(2/3) 测试通过` |
| `/great` | `🤩(3/3)` |
| `/neutral 收到` | `😐 收到` |

## 4. 命令注册与输出规整

- **注册**：`config` 钩子在 `cfg.command` 写入 `{ description, template }`；模板即 `emoji(等级/3) $ARGUMENTS`（中性为 `😐 $ARGUMENTS`）。只注册主命令，每个命令一条（不设别名）。
- **替换**：`$ARGUMENTS` 由 opencode 原生替换为用户参数；命令显式、无「符号边界」判定。
- **尾部空白清理**：无参数命令替换后模板残留尾部空格（`😊(2/3) `），由 `chat.message` 钩子用 `trimAnnotationTail` 清理为 `😊(2/3)`；`chat.message` **不再改写消息语义**。
- **幂等**：`chat.message` 只对**以情绪标注开头**的文本去尾部空白，普通消息原样不动；重复处理不再变化。

## 5. 架构

- **项目**：独立仓库 `opencode-emotions`，TypeScript + ESM，`tsc` 构建到 `dist/`
- **依赖**：
  - `dependencies`：`@xiaoqiong0v0/opencode-plugin-logger`（日志）、`ws`（阿里云 ASR/TTS 的 WebSocket 客户端）
  - `optionalDependencies`：`ffmpeg-static`（**自包含唯一来源**；按 `FFMPEG_BIN` → `ffmpeg-static` 顺序解析，两者都须通过 `-version` 真执行校验，不再回退系统 PATH；Termux 例外用系统 `ffmpeg`）
  - `peerDependencies`：`@opencode-ai/plugin`（宿主提供的插件类型与契约）
- **插件形态**：V1 默认导出 `{ id, server }`（本机本地/file 插件的可靠形态）
- **钩子**：
  - `config`：注册情绪命令
  - `tool`：注册 `emotions_cli` 工具（语音输出；定义见 `src/voice/tool.ts`，详见 `docs/设计-语音输入注入.md` §9/§12）
  - `chat.message`：清理标注文本的尾部空白（不改写语义）
- **情绪模型 / 标注生成**：`src/lib/emotions.ts`（纯函数：`Emotion` → `renderAnnotation`）
- **命令定义**：`src/lib/commands.ts`（命令表 + 模板生成）
- **标注文本工具**：`src/lib/parser.ts`（`trimAnnotationTail`；符号解析已删除）
- **状态**：无状态
- **日志**：`@xiaoqiong0v0/opencode-plugin-logger`
- **本地加载（开发）**：`tsc` 产物由 `npm run publish:proj` 镜像到项目 `.opencode/plugin/` 后重启 opencode

## 7. 已知限制与风险

- 命令由 opencode 原生解析：需真正触发命令（行首 `/`）才生效；普通消息不会产生标注。
- 语音来源的情绪映射尚在约定中（见 `docs/设计-语音输入注入.md` §4.3 / §8），与命令共用同一标注格式。
- 历史符号入口的限制（行首半角 `!` 被 shell 模式拦截、`?`/`666` 误伤、全角省略号不识别等）**随符号解析移除一并作废**，不再适用。

## 9. 情绪来源可插拔（命令 / 语音）

- 情绪标注由统一的**内部情绪模型**产出（`{情绪族, 等级}` → `emoji(等级/3)`）；任何来源都归一到它，新增来源不改标注格式，见 `src/lib/emotions.ts`。
- **命令来源（本插件）**：已实现（`config` 注册）。
- **语音来源（已实现，见 `docs/设计-语音输入注入.md`）**：TUI 插件把识别结果（文本 + 情绪）注入会话 / 输入框，情绪经映射表转成同一内部模型，产出同一 `emoji(等级/3)` 标注；**不再经过手动符号**。
- **分层**：「情绪模型 / 标注生成」与「输入来源」解耦——序列来源只需产出 `Emotion`，渲染与写回逻辑复用。
