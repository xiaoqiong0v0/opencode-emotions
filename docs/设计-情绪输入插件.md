# opencode-emotions 设计（v0.2 冻结版）

> 状态：设计已冻结，待实现 ｜ 日期：2026-10-09 ｜ 更早的 v0.1 符号体系（`6`/`1` 分数轴）已作废

## 1. 背景与目标

模型看不到用户的表情/情绪，容易误读语气。本插件给用户一个**极短的输入通道**表达当前情绪，并把简写**归一化为可见的情绪标注**写回消息，让模型读到准确的情绪信息。

设计原则：
- 输入极短、直觉（标点/数字串）
- 输出**零自然语言**（`emoji(等级/3)`），天然免 i18n、跨模型自解释
- 无状态，只作用于**当前这条消息**

## 2. 输入方式（两种）

### 2.1 前缀符号

**符号表**

| 符号（全/半角） | 情绪 | 最少个数 | 等级换算（封顶 3） | 1/3 | 2/3 | 3/3 |
|---|---|---|---|---|---|---|
| `!` / `！` | 怒 | 1 | `min(n, 3)` | 😠 | 😡 | 🤬 |
| `?` / `？` | 疑惑 | 1 | `min(n, 3)` | 😕 | 🤔 | 😵 |
| `...` / `。。。` | 无语 | 3 | `min(n-2, 3)` | 😐 | 😑 | 😮💨 |
| `666` | 非常好 | 3 | `min(n-2, 3)` | 🙂 | 😊 | 🤩 |

- 统一公式：`等级 = min(个数 - (最少个数 - 1), 3)`
- 只认同一种符号的连续串，不允许混写（`!?` 不认）
- 只作用于**当前这条消息**，命中后符号被**消耗**
- **宽度**：`!` / `?` 全角半角都识别；无语认半角 `.` 与全角句号 `。`（等价、各计 1、最少 3 个）；省略号 `……` / `…` 不识别

### 2.2 情绪命令（英文、带参数）

- 例：`/angry 需求又改了` → `😡(2/3) 需求又改了`
- 由插件通过 `config` 钩子注册；每个命令绑定固定「情绪 + 等级」
- 无参数时只产生标注本身
- 占位符用 **`$ARGUMENTS`**（实测有效；`{{input}}` 无效）

**命令集**

| 命令 | 别名 | 标注 |
|---|---|---|
| `/annoyed` | `/meh` | 😠(1/3) |
| `/angry` | `/mad` | 😡(2/3) |
| `/furious` | `/rage` | 🤬(3/3) |
| `/confused` | `/puzzled` | 🤔(2/3) |
| `/speechless` | `/sigh` | 😑(2/3) |
| `/neutral` | `/calm` | 😐 |
| `/ok` | `/fine` `/okay` | 🙂(1/3) |
| `/happy` | `/good` `/nice` | 😊(2/3) |
| `/great` | `/awesome` | 🤩(3/3) |

> 固定枚举，可增删；别名仅做同义映射。

## 3. 归一化输出

- 统一格式 **`emoji(等级/3)`**，不含任何自然语言
- 中性（无符号）不输出标注
- 标注统一置于消息**最前面**（结尾符号会上前）

**示例**

| 原始输入 | 归一化后 |
|---|---|
| `！！！测试` | `🤬(3/3) 测试` |
| `!!! 又崩了` | `🤬(3/3) 又崩了` |
| `又崩了 !!!` | `🤬(3/3) 又崩了` |
| `？？？ 这是啥` | 😵(3/3) 这是啥 |
| `... 算了` | 😐(1/3) 算了 |
| `..... 服了` | 😮💨(3/3) 服了 |
| `666 这版真不错` | 🙂(1/3) 这版真不错 |
| `666666 太强了` | 🤩(3/3) 太强了 |
| `!!!`（只发符号） | 🤬(3/3) |
| `/angry 需求又改了` | 😡(2/3) 需求又改了 |

## 4. 解析规则（token 边界）

- **独立 token**：符号串两侧须为**空白或行首/行尾**；只认**首个 token 或末尾 token**，正文中间的符号不认
- **开头符号**：
  - 标点类（`!` `?` `...`）**可直接接正文**（`！！！测试`、`...算了` 有效）
  - 数字类（`666`）**必须后跟空白或行尾**（防 `666元`、`666折`）
- **结尾符号**：不强制前置空格，但**至少 2 个**（`崩溃了！！！` 有效；`好开心！` 因只有 1 个不误伤）
  - 理由：`！`/`？` 在中文句尾是最普通的标点，单个会大量误伤；≥2 个才是有意表达情绪
- **冲突**：首尾同时出现 → 取**开头**；多条命中 → 取**首个 token**
- **只发符号**：整条消息只有符号时，正文即标注
- **幂等**：命中后符号被替换为 `emoji(n/3)`，二次处理不再匹配 → 不会重复叠加

## 5. 架构

- **项目**：独立仓库 `opencode-emotions`，TypeScript + ESM，`tsc` 构建到 `dist/`
- **依赖**：
  - `peerDependencies`：`@opencode-ai/plugin`
  - `dependencies`：`@xiaoqiong0v0/opencode-plugin-logger`
- **插件形态**：V1 默认导出 `{ id, server }`（本机本地/file 插件的可靠形态）
- **钩子**：
  - `config`：注册情绪命令
  - `chat.message`：解析前缀、改写 `output.parts` 为可见标注
- **解析逻辑**：纯函数（可单测），放 `lib/`
- **状态**：无状态
- **日志**：`@xiaoqiong0v0/opencode-plugin-logger`
- **本地加载（开发）**：`tsc` 产物拷到项目 `.opencode/plugin/` 后重启 opencode

## 7. 已知限制与风险

### 7.1 opencode 的 `!` shell 模式（硬限制）
- 半角 `!` 键在**光标位于首字符**时进入 shell 模式，回车**直接执行**且**不走权限确认**（`packages/tui/src/component/prompt/index.tsx:829-841`）；**不可配置禁用**。
- 影响：**行首半角 `!` 到不了插件**；行首**全角 `！`** 正常。
- 应对：行首用全角 `！`；行尾半/全角皆可。

### 7.2 残留误伤可能
- `? 这是什么`（疑问句）、`666 元`/`666 折`（数字）等仍可能被误判；token 规则已尽量收窄，但无法 100% 消除。
- 缓解：误判时用户可改用命令或改写措辞。

## 9. 后续扩展：情绪来源可插拔（语音 / ASR）

- 本版只实现「手动来源」（符号 + 命令）。
- 情绪标注由统一的**内部情绪模型**产出（`{情绪族, 等级}` → `emoji(等级/3)`）；任何来源都归一到它，新增来源不改标注格式。
- **语音来源（后续，本版不做）**：
  - 入口：**消息可直接注入** + 一个命令开关语音识别（如 `/voice`）。
  - ASR **可插拔**（provider 配置：API key / endpoint）。
  - ASR 返回分类情绪（happy/angry/sad/… + 置信度）→ 经**映射表**转成内部情绪模型 → 同一 `emoji(等级/3)` 标注。
- 实现时把「情绪模型 / 标注生成」与「符号解析」**分层**，便于后续加来源。
