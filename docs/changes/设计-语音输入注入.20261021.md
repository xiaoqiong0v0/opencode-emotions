# 变更说明：修自动朗读四缺陷——碎块冷启动 / 杀父不杀孙 / interrupt 被流式淹没 / 空文本（2026-10-21）

对应原文档：`docs/设计-语音输入注入.md` §15.2 打断、§15.3 增量自动朗读；`docs/ASYNC.md` 交互点 ⑫⑬与不变量 41/48/49/55。
改动 `src/voice/auto-read.ts`、`src/voice/playback-state.ts`、`src/voice/tts/types.ts`、`src/voice/tts/sapi.ts`、
`src/cli/emotions-cli.ts`、`src/lib/i18n.ts`。

## 现象（用户实测四缺陷，证据已取齐）
1. **碎块×进程冷启动**：日志见 `len=1~8` 的块逐块 `tts speak provider=sapi` → 听感「两字一顿、很慢」。
2. **杀父不杀孙**：打断后当前块继续播完才停。
3. **interrupt 被流式淹没**：「发消息也停不掉这条」——清了队列，新 delta 又继续 enqueue、drain 重启。
4. **空文本块**：曾见 `Speech failed: text 不能为空`（子进程异常退出 warn）。

## 根因
1. `drain` 每 `queue.shift()` 一块就 `await spawnSpeak`——**每块 spawn 一个新 CLI**；provider=sapi 时每块都
   冷启动 PowerShell（`Add-Type` ≈1-2s）。spawn 期间 delta 持续到达把队列堆满 → 逐块冷启动，碎块感极强。
2. `stopPlayback` 只按 `tts-playback` 记录的 **CLI node PID** 杀；发声的 PowerShell 是 CLI 的**子进程**，
   Windows `TerminateProcess` **不杀子孙** → CLI 死了、孙进程把当前块播完。
3. `interrupt()` 只清队列+杀子进程，**没有消息级停止位**：消息仍在 `message.part.delta` 流式 →
   新 delta 继续 enqueue → drain 重启，等于没停。
4. 空/纯空白 chunk 未过滤：写进临时文件 → CLI `--text-file` 读后 `.trim()` 为空 → sapi `speak()` 抛
   「text 不能为空」→ 子进程非零退出 warn。

## 现在（修法）

### A. drain 凑批合并（消碎块）—— `src/voice/auto-read.ts` `drain()`
- 每轮 shift 出首块后，**继续 shift 拼接「此刻已在队列」的所有块**再 spawn 一次读一大段。
- **事件驱动**：只合并现成的块，**不等待/不轮询**新 delta（不在 drain 里等）。
- 单次合并上限 `DRAIN_MERGE_MAX_CHARS = 2000` 字：防单块超长（临时文件/单段合成过长）；超出的块留队列下次读。
  打断不依赖块边界（按 PID 杀进程即时生效），上限只是防御护栏。
- 日志 `自动朗读已触发：… len=…` 保留并补 **`chunks_merged=`**（本次合并数）——低噪且直接观测凑批效果。

### B. tts-playback 记两个 PID（消杀父不杀孙）
- `PlaybackEntry` 增**可选** `playerPid`（真正发声的孙进程 PID）；文件格式**向后兼容**（旧格式无该字段照常读，
  读出对象不新增键）。
- `TtsProvider` 接口增可选 **`activePlayerPid?(): number | undefined`**：**仅 sapi 实现**（返回 `this.child.pid`）；
  aliyun/mimo（流式 waveOut 靠 stdin EOF 自退，已工作）与 termux 不实现 → undefined。
- CLI `registerPlaybackLifecycle()` 登记时写 `playerPid: getProvider(result.provider).activePlayerPid?.()`。
  **时序**：`provider.speak()` 是**同步返回**的、PowerShell 在 `speak()` 内已 spawn ⇒ speak 返回后**读一次即可**
  （一次写盘、无轮询补写；注释已标明：若日后有 provider 改异步 spawn，此处需补「读到非空再写」）。
- `stopPlayback()`：目标 = `pid` ∪ `playerPid`（去重），**每个目标各自过红线**（`>1`、`≠自身`、存活；条目级 TTL）
  后先 `SIGTERM`、1.5s 后仍存活再 `SIGKILL`（两个目标都升级）；任一命中即返回 true。
  旧格式（无 `playerPid`）只杀 `pid`，与旧行为一致。`kill`/`isAlive`/`now` 仍可注入单测。

### C. interrupt 水位（消「停不掉这条」）—— `src/voice/auto-read.ts`
- 消息级 **`interrupted`** 标（`Set<messageID>`，LRU 上限 100）。`interrupt()` 现实不带 messageID →
  **对当前所有在途消息置位**：`streams` 有状态的 ∪ `diag` 已过门但尚无 StreamState 的（后者防其完成后走
  `runFallback` 回退整段读）；同时清队列+杀子进程（原有行为）。
- 置位后：`handleDelta`/`handlePart` 丢弃新块（不入文本）；`enqueue` 拒收；`drain` 派生前复查；
  `finalize` 直接 `seen.add` 封口**不补读**；`runFallback` 在取 parts 前与 spawn 前各复查一次（fetch 期间置位的并发兜底）。
- **不影响下一条消息**：新 messageID 不在集合 ⇒ 正常读。诊断：置位时打一条
  `自动朗读已打断：messages=N`（无在途消息时不打，防刷屏）；被跳过的 fallback 打 `skipReason=interrupted` 汇总。

### D. 空文本过滤
- `spawnSpeak()` 首行：`!text.trim()` → 直接 resolve（不写临时文件、不 spawn、不报错）。
- CLI `runSpeak()`：resolve 文本后 `!text.trim()` → 输出 `cli.speakSkipped`（zh/en 新增文案）并 `return 0`
  （不 `stopPlayback()`、不派生 `__play`、不触发 provider）。

## 为什么
- 1/3/4 均为用户实测（日志与听感证据齐全，见任务取证）；2 的机制（Windows `TerminateProcess` 不杀子孙）
  与 `tts-playback` 只记 CLI PID 的实现相互印证。
- 合并取「只拼现成块」而非「等一小段时间凑批」：等待即引入定时器与人为延迟，违背事件驱动；spawn 期间自然堆积的块
  已足够凑成大段（sapi 冷启动 1-2s 内通常已到多个 delta）。
- 水位用消息级 Set 而非 `StreamState` 字段：`interrupt()` 不带 messageID，且需覆盖「尚无 state 的在途消息」
  （fallback 路径），Set 在 delta/part/enqueue/drain/finalize/fallback 六处可统一查询。

## 代价 / 残余风险
- **B 时序**：CLI 在 `speak()` 返回到写盘之间的毫秒级窗口被杀 → 状态文件还没有 `playerPid`（或还是上一条的），
  孙进程可能短暂孤儿播放；极小窗口，未做「先写 pid 再补 playerPid」两段写（speak 前尚不知 provider 子进程）。
  另：speak 极快失败退出时 `activePlayerPid()` 为 undefined → 退化旧行为（只杀 CLI，安全）。
- **C 活跃消息判定**：置位覆盖 `streams`∪`diag`（保守：另一会话正在流式的消息也会被打断——与旧「清所有队列」口径一致）；
  **零事件消息**（插件启动后从未收到任何 part/delta）无从识别，完成时仍可能回退整段读（残余，已记入 ASYNC 不变量）。
- **A 合并改变块边界**：`chunks_merged>1` 时 `len=` 为合并后长度（诊断口径变化）；单块上限 2000 字是防御值，
  非服务端约束（`MAX_CONTINUE_CHARS` 2 万）。
- 行为反转（有意）：被打断的同一条消息**不再**「后续增量继续/重开」（旧行为），改为水位终止；下一条消息不受影响。

## 验证
`npm test` **211/211** 全绿（基线 203，净 +8：`auto-tts` 新增凑批合并/合并上限/空文本 3 例、
`playback-state` 新增 playerPid roundtrip·旧格式兼容/双 PID 双杀/逐 PID 红线 3 例、`tts` 新增
`activePlayerPid` 契约 1 例、`emotions-cli` 新增空白 `--text-file` 跳过 1 例；另**改写 1 例**
「interrupt 后仍可继续」→「interrupt 水位：同消息不再读、下一条正常」——行为反转非测试作弊，spec 明确要求）。
`npm run build`（tsc + TUI Babel）通过。日志见 `.tmp/scratch/autoread-fix-task.log`。

# 变更说明（同日第二批）：drain 句对齐切分 + sapi follow 常驻 worker（真修段间停顿）

对应原文档：`docs/设计-语音输入注入.md` §15.3/§15.4；`docs/ASYNC.md` 交互点 ⑫⑯ 与不变量 41/49。
改动 `src/voice/auto-read.ts`、`src/voice/cli.ts`、`src/cli/emotions-cli.ts`、`src/voice/tts/types.ts`、
`src/voice/tts/sapi.ts`、`src/voice/tts/index.ts`、`src/lib/i18n.ts`、`src/emotions.ts`。

## 现象（用户拍板真修）
第一批的凑批合并把碎块拼大段，但 sapi 每块仍冷启动 PowerShell（Add-Type ≈0.5-1s）→ **段间停顿仍明显**；
且块边界是「字符数硬断」，停顿可能落在句中。

## 现在（修法）

### A. drain 句对齐切分（所有 provider）
- 新纯函数 `splitDrainUnits(merged, max=2000)`（`auto-read.ts`，内部用现成 `splitSentences()`）：
  完整句按 ≤2000 贪婪连读成单元；**未完结尾段（tail）不进本批** → `StreamState.carry` 下一批拼接
  （块边界落在句尾）；**单句超上限才句内硬切**（唯一句中断点）；无标点 carry 超上限兜底硬切（防攒到 done）。
- `drain`：merge（carry+队列块 ≤2000）→ `splitDrainUnits` → 逐单元投递；消息 `done` 且队列/carry 空 →
  终态收敛（关 follow worker）。非 follow provider 仍每单元 spawn CLI（停顿落句尾）。

### B. `speak --follow` 常驻 worker（sapi）
- **CLI**：`--follow` 从 stdin 按行读 UTF-8 连续朗读（空行跳过、EOF 收尾）；与 `--text`/`--text-file`/
  `--background` 互斥（解析层报错）；provider 走 TTS_PROVIDER 解析链，不支持时 i18n 报错
  （`cli.followUnsupported` zh/en）exit 1。启动即 `writePlayback`（pid+playerPid），SIGTERM → `provider.stop()`。
- **能力位**：`TtsProvider.followSupport?`（sapi=true）+ 可选 `followStart/followLine/followEnd`；
  `resolveFollowSupport()`（env→config→默认）供生产接线。
- **sapi**：`SAPI_FOLLOW_SCRIPT` = 一次 PowerShell + `[Console]::In.ReadLine()` 循环（stdin UTF-8，
  `$null -ne` 判定防空行误退出），`Speak` 同步=天然串行；`followStart` 同步 spawn（`activePlayerPid()` 即其 PID）、
  `followLine` 写 stdin、`followEnd` 关 stdin 等退出（30s 超时强杀）。普通 `SAPI_SCRIPT`/`speak()` **不变**
  （`speak()` 仍先 `stop()` 杀 follow 子进程）。
- **auto-read**：`deps.followSupport`（生产=`resolveFollowSupport()`，测试注入定值防环境漂移）；
  每消息 1 worker：首句 `spawnWorker`（`speak --follow`，入 `activeChildren`）→ 后续 `writeWorkerLine`
  （背压等 drain ≤5s）→ finalize/中止 `closeWorker`（关 stdin 等退出 ≤30s）。**worker 天折**：写失败 →
  warn + 该消息置 `interrupted`（水位同语义：不补读、seen 封口），不影响下一条；spawn 失败 → `followBroken`
  退回按块 spawn。日志：worker 启动 1 条 info、块级静默（`Logger` 无 debug）；非 follow 路径
  `自动朗读已触发` 移除 `chunks_merged=`（句对齐后无意义）。

## 代价 / 残余风险
- **首句延迟口径变化（有意）**：首个朗读单元等到第一个句末标点（或消息完成）才发出——`streamMinChars`
  管「何时开始缓冲」，句边界管「何时派生」；长时间无标点的输出攒到 done 或 carry 超 2000 兜底硬切。
- **worker 是每消息一个**：消息间仍有一次 spawn（PowerShell 冷启动每消息一次，非每块）；跨消息复用需
  引用计数（未做）。
- **stdin 编码**：follow 脚本设 `[Console]::InputEncoding=UTF8`（try/catch 防无控制台环境）；Node 侧
  `stdin.setEncoding("utf8")`。**背压**：行很小 + Speak 慢，`write()===false` 罕见，等 drain 5s 兜底。
- **follow 中途 PowerShell 死**：worker CLI `followLine` 抛错 → exit 1 → auto-read 写失败 → 该消息停读（链路闭环）。
- 回退路径 `runFallback`（整段读）**不走 worker**（单次 `--text-file` spawn，行为不变）。

## 验证
`npm test` **219/219** 全绿（基线 211，净 +8：`auto-tts` +5——`splitDrainUnits` 纯函数/句对齐 carry/无标点
超长硬切/follow worker 生命周期/follow worker 天折、`tts` +2——SAPI_FOLLOW_SCRIPT/follow 能力位、
`emotions-cli` +2——`--follow` 解析互斥/不支持 provider i18n 报错；**改写 5 例**为句对齐新 spec：
「阈值…逐增量发（不做句切分）」→「句尾对齐才派生」、子会话/F10/delta 流式/角色补取的 fixture 补句号、
凑批合并 2 例改句对齐断言并以 `splitDrainUnits` 直测承接上限场景——行为反转非测试作弊，spec 明确要求）。
`npm run build` 通过。`SAPI_FOLLOW_SCRIPT` 真实 PowerShell 空 stdin 冒烟 exit 0 无 stderr。
日志见 `.tmp/scratch/sapi-follow-task.log`。真实连续播放/段间无冷启动停感/打断双杀需部署重启后由用户验证。

# 变更说明（同日第三批）：打断按 sessionID 隔离——修跨会话误杀（句子中间被杀在句）

对应原文档：`docs/设计-语音输入注入.md` §15.2 打断（含 §14.2 F10 提法）；`docs/ASYNC.md` 交互点 ⑫⑬⑯ 与不变量 42/49/54。
改动 `src/voice/playback-state.ts`、`src/cli/emotions-cli.ts`、`src/voice/auto-read.ts`、`src/emotions.ts`、`src/tui.tsx`。

## 现象（用户实测，日志取证齐全）
用户听感「读到 就剩 就停了」——本会话正在播的 sapi follow worker（CLI + PowerShell 双 PID）在**句子中间**被杀。
plugins-log 证据：`10:58:00 worker 异常退出 code=1`，与**同一秒**另一会话的
`自动朗读子会话判定 session=ses_ea39b1541` 对齐——即另一窗口新会话来消息的瞬间本会话播放死亡。

## 根因
`src/emotions.ts` 的 `chat.message` 对**任意窗口任意会话**的消息都无条件 `stopPlayback()`，而
`tts-playback` 状态文件是**全局单文件**（跨会话共用、按 PID 停）——B 会话的消息把 A 会话登记的
worker 双 PID 全杀（含 `SIGKILL` 升级），于是 A 的句子被腰斩。文件「留 base 根」的既有决策没错，
错在**打断方不看归属**。

## 现在（修法）

### A. 条目记会话归属（`src/voice/playback-state.ts` + 写入侧）
- `PlaybackEntry` 增可选 **`sessionID`**；`readPlayback` 非空字符串才带键（旧格式读出**不新增键**=无主，同 `playerPid` 口径）。
- 传递链走 **env `EMOTIONS_SESSION_ID`**（常量 `PLAYBACK_SESSION_ENV`，**免改 argv 解析**）：
  - `auto-read.ts` `spawnSpeak`/`spawnWorker` 派生 CLI 时 `env: { ...process.env, EMOTIONS_SESSION_ENV: sessionID }`
    （两处；sessionID 分别取自 `state.sessionID` / `runFallback` 入参——**消息所属会话**）；
  - `emotions-cli.ts` `registerPlaybackLifecycle()` 登记时 `sessionID: process.env[EMOTIONS_SESSION_ENV]?.trim() || undefined`
    （speak 前台 / `__play` 后台（env 经 spawn 继承）/ `speak --follow` 三路**共用同一登记函数**——
    `runSpeakFollow` 原重复的 `writePlayback`+信号收尾块并入，消除三处发散风险）。

### B. `stopPlayback(options?: { sessionID })` 语义（会话归属门，先于 TTL/杀流程）
| 调用 sessionID | 条目 sessionID | 行为 |
| --- | --- | --- |
| 无参 / 空白 | 任意 | **停**（停任意——CLI 新播放前清场保持此语义） |
| 非空 | 缺失（旧格式/手动 speak） | **停**（无主播放任何消息都可打断，向后兼容） |
| 非空、相等 | 相等 | **停**（同会话；红线流程不变：pid∪playerPid 逐 PID、TERM→KILL、pid>1、不杀自身） |
| 非空、不等 | 存在且不等 | **不杀、不清状态**，返回 false（跨会话不误杀） |

日志（`createLogger("playback")`，低噪一行）：成功停止 `stopped playback session=<sessionID 或 -> provider=<…>`；
跨会话跳过 `skipped cross-session stop: session=… entry=… provider=…`。

### C. 调用点收窄
- `src/emotions.ts` `chat.message`：`stopPlayback({ sessionID: input.sessionID })`（钩子入参已含 sessionID，
  类型 `@opencode-ai/plugin` dist/index.d.ts `chat.message` input）。
- `src/tui.tsx`：F8/F9 `toggleMode()` 传 `{ sessionID: currentSessionID(api) }`（取不到路由 → 退化停任意，旧行为）；
  F10 `toggleAutoRead()` 关闭传 `{ sessionID }`（本会话开关只停本会话）。
- `emotions-cli.ts` 三处**新播放前清场保持无参**（跨会话清场是既有语义：新播放必先打断上一条）。

## 代价 / 残余风险（有意保留）
- **手动 speak（`emotions_cli` 工具 / 命令行）不设 env ⇒ 条目无主，仍可被任意会话的任何消息打断**——
  有意兼容（无主播放视为全局；工具链要隔离需另传 sessionID，本轮不做）。
- `chat.message` 的 `autoReader.interrupt()`（队列/水位）仍**进程内全局**（另一会话在途消息也被清队列）——
  与 C 水位「旧口径已接受」的残余一致，本轮只修 PID 误杀（播放不再被腰斩，队列清空不影响已发声部分）。
- 跨会话条目在 TTL 过期前不会被「跨会话路径」清理，只由同会话/无参路径清理——瞬态自清语义未变。

## 验证
`npm test` **228/228** 全绿（基线 219，净 +9：`playback-state` +4——sessionID roundtrip·跨会话不杀不清·
无主兼容·无参/空停任意、`auto-tts` +2——spawnSpeak/spawnWorker env 注入、`emotions-cli` +1——env→条目 sessionID、
新增 `test/emotions-hook.test.js` +1——chat.message 按 input.sessionID 隔离（临时 HOME 隔离状态根、
pid=自身零真实信号）、`tui-diagnostics` +1——产物无裸 `stopPlayback()`、两处均带 sessionID；
既有用例**未改断言**——无参语义不变、新签名全可选）。`npm run build`（tsc + TUI Babel）通过。
日志见 `.tmp/scratch/session-scoped-stop-task.log`。跨窗口真实打断隔离需部署重启后由用户验证。

# 变更说明（同日第四批）：interrupt 按 sessionID 收窄 + 跨会话共享状态全量盘点

## 现象（第三批自曝残余，本批补完）
第三批只修了 **PID 半边**（`stopPlayback` 会话门），`autoReader.interrupt()`（`chat.message` 触发）仍**进程内全局**——
一个窗口多会话/主+子会话并行时，A 会话发消息会：① 清空**所有**会话在途消息的待读队列；
② kill **所有** `activeChildren`（含其它会话的 CLI/worker 子进程，**绕过 stopPlayback 会话门**）；
③ 把**所有**在途消息的 `interrupted` 水位置位——其它会话这条消息**永久停读**（delta 丢弃、完成不补读）。

## 根因
`interrupt()` 不带任何范围参数，三处动作（清队列/置水位/杀进程）的目标集合都是「进程内全部」：
`activeChildren` 是裸 `Set<ChildProcess>`（无归属信息，只能全杀）；`diag` 的 `MessageDiag` 无 `sessionID`
字段（「已过门但尚无 StreamState」的在途消息无从按会话过滤）。第三批改签名时只动了 `stopPlayback`。

## 现在（修法）

### A. `interrupt(sessionID?: string)` 语义（`src/voice/auto-read.ts`）
| 调用 | 队列 | 水位（`interrupted`） | 子进程 kill |
|---|---|---|---|
| 带非空 sessionID | 只清 `state.sessionID ===` 它的 | 只置该会话的在途消息（`streams`+`diag` 按 sessionID 过滤） | 只杀 `activeChildren` 归属该会话的 |
| 无参 / 空白 | 全清（原行为） | 全置（原行为） | 全杀（原行为，dispose/清场路径不变） |

诊断行带范围：`自动朗读已打断：messages=N[ session=<id>]`（收窄时带 session 后缀）。

### B. 归属结构
- `activeChildren`：`Set<ChildProcess>` → **`Map<ChildProcess, { messageID, sessionID }>`**
  （`spawnSpeak`/`spawnWorker` 登记归属；exit/error 回调仍 `delete(child)`）。
  收窄 kill 后**不立即摘条目**——留待 exit 回调摘除，kill 失败但进程仍活时不丢追踪（全清路径照旧 `clear()`）。
- `MessageDiag` 增 **`sessionID`** 字段（`diagFor(messageID, sessionID)`，三处调用点传入：`handlePart`/`handleDelta`/`enqueue`）——
  否则「已过门但尚无 StreamState」的在途消息在 interrupt 收窄时会被漏置水位（退化回跨会话口径）。

### C. 调用点（grep 全量：生产仅 1 处）
- `src/emotions.ts` `chat.message`：`autoReader?.interrupt(input.sessionID)`；
  sessionID 缺失/空白 → `interrupt` 内部退化全清（与 `stopPlayback` 「取不到才停任意」同口径）。
- dispose/stopRuntime：**本插件无此类调用**（server 无 dispose 钩子、TUI dispose 只停 runtime 子进程）——
  无参语义由测试回归钉住（`interrupt() 无参回归`、`只 kill…无参全杀`）。
- TUI F10/F8/F9 不调 `interrupt`（它们只走 `stopPlayback({sessionID})`），无需改。

## 盘点结论（全量表见 `.tmp/scratch/session-isolation-audit.md`；结论已沉淀 ASYNC 不变量）
- **已隔离**：`auto-tts`/`auto-tts-seen`（每会话目录）、`tts-playback` 打断侧（会话门）、`tts/` 临时正文

- **缺口 3 → 本批全修**：`interrupted` 水位、待读队列清空、`activeChildren` 杀进程（+支撑字段 `diag.sessionID`）。
- **有意全局（登记不变量）**：`emotions.jsonc` 配置、`resetAutoTtsState` 重启清场、TUI 语音模式（窗口级）、

## 代价 / 残余风险
