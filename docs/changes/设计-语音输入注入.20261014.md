# 变更说明：语音配置文件名与插件同名（2026-10-14）

对应原文档：`docs/设计-语音输入注入.md` §10（配置化）。

## 原
- 默认配置文件名 **`<配置目录>/voice.jsonc`**（早期按「语音功能」命名，与插件名无关）。
- 覆盖配置目录的环境变量为 **`VOICE_CONFIG_DIR`**（只有这一个旧名）。

## 现在
- 默认配置文件名改为 **`<配置目录>/emotions.jsonc`**（= 去掉 `opencode-` 前缀的项目名，与同级插件约定一致：
  `opencode-browser-tool`→`browser-tool.jsonc`、`opencode-sound-notify`→`sound-notify.jsonc`、
  `opencode-plugin-logger`→`plugin-logger.jsonc`）。常量 `CONFIG_FILE_NAME`（`src/voice/config.ts`）。
- **向后兼容**：
  - `loadVoiceConfig()` 里新增迁移——`emotions.jsonc` 不存在而 `voice.jsonc` 存在时，把旧文件**原样复制**为
    `emotions.jsonc`（不改用户任何配置值、**旧文件保留不删**），随后按新名读取；两者都在时只读新名。
    新增常量 `LEGACY_CONFIG_FILE_NAME`、导出 `legacyVoiceConfigPath()`。
  - 环境变量新名 **`EMOTIONS_CONFIG_DIR`**，旧名 **`VOICE_CONFIG_DIR`** 继续可读；两者同时设置时**新名优先**
    （`resolveConfigDir()` 新增 `envNames` 参数，按顺序取第一个非空）。
- 其余 `VOICE_*`（`VOICE_DEVICE` / `VOICE_ASR_*` / `VOICE_VAD_*` / `VOICE_ALIYUN_CREDENTIALS` …）与 `TTS_*`
  **不改名**：它们是「语音字段/运行时」的覆盖开关，不指代配置文件本身。

## 为什么
- 配置文件名跟插件名走是本机 opencode 插件的既有约定，`voice.jsonc` 是例外；同名后一眼可知归属，
  也便于按插件名清理/备份配置目录。
- 只改默认文件名与环境变量新名、保留旧名读取与自动迁移，避免用户升级插件后配置静默失效（值丢失）。

## 追加（同日）：TTS 工具改 CLI 风格 + 情绪 + i18n + 槽位单词条

对应原文档：`docs/设计-语音输入注入.md` §3、§9、§12、§13。

### 原
- TTS 工具名 `speak`，参数是 `text`/`voice`/`rate` 三个字段，`execute` 直接调内存里的 provider。
- 语音输出**无情绪**（只有 `tts.instruction` 配置项，需用户手填指令）。
- 所有面向用户/模型的文案**硬编码中文**（工具描述、toast、槽位、命令标题）。
- 输入框右侧渲染**两个**指示元素（`🎙注入○` / `🎙输入○`）。

### 现在
- **CLI 风格工具** `voice_cli`（照本机 `stats-command.js` 模式）：参数只有 `args` 字符串，`execute` 用 `exec` 运行
  `node dist/voice-cli.js <args>`（`windowsHide`、64MB `maxBuffer`；找不到 `node` 回退 `process.execPath`），返回 `{ title, output }`。
  新增 CLI 入口 `src/voice-cli.ts`（→ `dist/voice-cli.js`）：`speak` / `devices` / `status` / `help`（+ 内部 `__play`）。
- **情绪**：`speak --emotion <name>` 映射为 CosyVoice `instruction`（`src/voice/tts/emotion.ts`，别名表见 §13.1）；sapi 忽略；覆盖优先级 `--emotion` > `TTS_INSTRUCTION` > `tts.instruction`。
- **i18n**：配置新增 `language`（`zh`/`en`，默认 `zh`；env `VOICE_LANGUAGE`），词表集中在 `src/lib/i18n.ts`（`PHRASES` + `format()`）；
  覆盖工具描述（插件加载时本地化）、TUI 槽位/toast/命令标题、`voice-cli --help`。
- **槽位单词条**：改为 `[🎙状态][注入|输入][F8/F9]`（`🎙 ● 注入 F8/F9` / `🎙 ○ 输入 F8/F9` / `🎙 ⏳ …`；第三段恒为两键 `F8/F9`，作「可按 `F8`=注入 / `F9`=输入 切换」提示、**不随模式变**；**emoji 后留空格防重叠**），渲染纯函数 `src/voice/slot.ts`。
- **进程模型**：`speak --background` 前台校验后 `spawn(detached).unref()` 派生 `__play` 播放（参数经 base64 环境变量传递），保持「不卡回合」。

### 为什么
- 与 `stats_cli` 统一交互形态：模型只给一条参数串，能力全在 CLI，工具零业务逻辑；命令行可独立复用/调试。
- 情绪是「同一份文字换语气」的自然需求，CosyVoice 的 `instruction` 是官方风格化入口。
- 文案集中 + 语言可配，避免硬编码中文、便于扩展语言。
- 两个模式各占一个指示不直观，合并后「状态+模式+热键」一眼可读。

### 代价（已知限制，见 ASYNC）
- **跨进程不保证打断**：工具每次调用各派生独立 `__play`，两条并发朗读不互相打断（同进程内仍先 `stop()`）。
- **dispose 不再 stop**：分离播放进程无跨进程句柄，opencode 退出不主动停止正在播放的语音（正常播完自行退出）。

## 追加（同日）：CLI 产物不得放在插件目录（启动误打印 help）

对应原文档：`docs/设计-语音输入注入.md` §9、§12.1。

### 原
- CLI 入口 `voice-cli.js` 被**拷到 `.opencode/plugin/` 顶层**（与 `emotions.js` / `tts-tool.js` 并列），且 `src/voice-cli.ts` **顶层直接执行** `main(process.argv.slice(2))`。
- 症状：opencode **启动时刷出 voice-cli 的 help 文本**——因为 opencode 会把 `.opencode/plugin/` 顶层的**每个 `.js` 当插件 import**，`voice-cli.js` 被 import → 空参数跑 `main([])` → 打印 help。

### 现在
- `src/voice-cli.ts` 加**入口保护** `isDirectEntry()`：仅当 `realpath(process.argv[1]) === realpath(import.meta.url)` 才执行 `main()`；被 import 时**不执行、不打印**。
- **部署约定改为「CLI 产物只留 `dist/`，不拷入 `.opencode/plugin/`」**；工具解析顺序 `VOICE_CLI_SCRIPT` > `<cwd>/dist/voice-cli.js` > 由插件位置上溯的 `<仓库根>/dist/voice-cli.js`。
- `.opencode/plugin/` 顶层**只允许真正的插件模块**（现为 `emotions.js`、`tts-tool.js`；`lib/`、`voice/` 为子目录，不被扫描）。

### 为什么
- `.opencode/plugin/` 顶层就是插件加载目录，任何可执行脚本放这里都会被当插件执行（与历史上「产物没 render 又写进 jsonc 数组导致加载失败」同类）。
- 双重防护（入口保护 + 不放入插件目录）：即便日后误拷回顶层，也不会再刷屏。

### 代价
- 工具需从 `<cwd>/dist` 或「插件位置上溯的仓库根 `dist/`」解析 CLI，依赖 `dist/` 已构建（本地开发即如此）。

## 追加（同日）：槽位指示**分段配色**

对应原文档：`docs/设计-语音输入注入.md` §3（TUI 槽位形态）。

### 原
- 槽位整条指示由**单个** `<text>` 渲染、**单色**：有模式开启时整条 `theme.success`，否则整条 `theme.textMuted`
  （`src/tui.tsx` `session_prompt_right`；文本由 `formatSlotIndicator` 一次给出，无分段概念）。

### 现在
- **分段**：`src/voice/slot.ts` 新增纯函数 `formatSlotSegments(phrases, { mic, mode, injectOn, inputOn })`，
  产出 `{ text, role }[]`（角色 `icon`/`glyph`/`mode`/`keyActive`/`keyInactive`/`separator`，**不含颜色值**）；
  `formatSlotIndicator` 改为「分段拼接后的纯文本」（文本与旧行为逐字节一致，旧断言不变）。
- **逐段上色**（`src/tui.tsx`）：`<For>` 按 `role` 选 `api.theme.current` 颜色键、每段一个 `<text fg>`：
  - `🎙` 图标与 `●`/`○`/`⏳` 字形：`success`（开）/`info`（启动中）/`textMuted`（关）；
  - 模式描述 `注入`/`输入` 与「激活热键」：注入=`warning`、输入=`primary`（固定两色）；
  - 激活的热键用其模式色（注入激活→`F8`=`warning`；输入激活→`F9`=`primary`），未激活热键与 `/` 用 `textMuted`；
  - 关闭态（无激活模式）：模式描述与两键也取 `textMuted`（描述仍显示上次模式但整体转暗）。
- 颜色键经 `@opencode-ai/plugin` `dist/tui.d.ts` 的 `TuiThemeCurrent` 实证（`primary/secondary/accent/success/warning/info/text/textMuted` …），不使用未定义键。

### 为什么
- 单色整条看不出「当前是哪个模式、哪个键生效」；分段后状态、模式、激活键各自可辨，且关闭态有一致的「整体转暗」读法。
- 文本与配色分离：`slot.ts` 仍可离线单测（返回分段文本），颜色只在渲染层（`api.theme`）决定，纯函数不被宿主类型污染。

### 代价
- `src/tui.tsx` 不在 `tsc` 构建范围（`tsconfig.json` `exclude`；由 TUI 宿主以 SolidJS 链路编译），其分段渲染**不参与 `npm run build` 类型检查**，仅由宿主运行时验证。

## 追加（同日）：槽位指示**总宽恒定**（可变段按语言预计算最大宽度 + 定宽填充）

对应原文档：`docs/设计-语音输入注入.md` §3（TUI 槽位形态）。

### 原
- 槽位可变段**直接拼接**：状态字形段 `字形 + 空格`、模式描述段 `模式名 + 空格`。
- 症状：切换 `F8`/`F9` 或 mic 状态时**整条指示宽度抖动**——`●`/`○` 在该渲染口径下为 1 列、`⏳` 为 2 列
  （启动态比开/关态宽 1 列）；英文 `Inject`(6) 与 `Input`(5) 相差 1 列（`注入`/`输入` 同为 2 列故中文不抖）。

### 现在
- `src/voice/slot.ts` 新增纯函数 `displayWidth(text)`，口径复刻渲染库 `@opentui/core` 内联的 `string-width@7`
  （Bun 宿主下为 `Bun.stringWidth`，`ambiguousIsNarrow:true`）：零宽/组合/控制符计 0，emoji 与 East Asian
  Wide/Fullwidth 计 2，其余（含歧义宽度）计 1 ⇒ `●`/`○`=1、`⏳`/`🎙`=2、CJK=2、ASCII=1。
- 新增 `GLYPH_SEGMENT_WIDTH`（Wg = 状态字形段含尾随空格的最大宽度，当前 3）与 `modeSegmentWidth(phrases)`
  （Wl = 该语言全部模式描述段含尾随空格的最大宽度，按 `Phrases` 用 `WeakMap` 缓存；zh=5、en=7）。
- `formatSlotSegments` 对**状态字形段**补空格到 Wg、对**模式描述段**补空格到该语言 Wl；图标与 `F8/F9` 段不动。
  拼接总宽恒定：`zh`=16、`en`=18（口径实测：`string-width@7.2.0` 与 `displayWidth` 逐条一致）。
- `src/tui.tsx`：`session_prompt_right` 由 `<For each={segments}>` 逐段重建改为**静态结构 + 响应式文本**——
  固定 6 个 `<text>` 节点，文本/颜色经响应式访问器读取；消除分段数组变化时节点销毁/重建造成的闪烁。

### 为什么
- 定宽填充是「按当前语言预计算可变段最大宽度、再补齐」的最直接实现：填充只作用于**短的那一侧**，
  长段（如 `⏳`、`Inject`）不被截断，故任意 mic 状态 × 模式 × 语言下总宽恒定，不会跳动。
- 单一元素 + 定宽使「状态/模式/热键」位置固定，视觉上不再左右抖动。

### 代价
- 开/关态字形后会多出补齐空格（`🎙 ●  注入 …` 两空格），视觉上有轻微空隙——这是换取总宽恒定的代价。
- `displayWidth` 为渲染口径的**近似复刻**（覆盖 emoji 与常见 Wide/Fullwidth 区段）；本项目 `zh`/`en` 与三个字形
  取值与渲染库完全一致，新增语言若含复杂 emoji/ZWJ 序列需复核（见原文档 §3 宽度口径说明）。
- 既有单测断言（精确字符串）按新填充行为更新；`src/tui.tsx` 仍不在 `tsc` 范围，仅由宿主运行时验证。

## 追加（同日）：发布结构重排（dist 镜像即可发布；TUI 编译成 js）

对应原文档：`docs/设计-语音输入注入.md` §9、§12.1、§12.2。

### 原
- `dist/` 顶层混放插件与非插件：`index.js`、`tts-tool.js`、`voice-cli.js`、`voice-runtime.js` 全在同一级；
  本地发布需**手动挑拣/改名**拷入 `.opencode/plugin/`。
- TUI 插件由宿主在装载时自行编译 `src/tui.tsx`（`tsconfig` `exclude`，`tui.json` 直指 `../src/tui.tsx`），
  无 `dist/tui.js`、无 npm `exports["./tui"]`。
- 无 `publish:proj`；`main`/`exports` 指向 `dist/index.js`。

### 现在
- **源重排**：`src/index.ts`→`src/emotions.ts`；`src/voice-cli.ts`→`src/cli/voice-cli.ts`；
  `src/voice-runtime.ts`→`src/runtime/voice-runtime.ts`；`src/tui.tsx` 原位。相对 import 全部同步。
- **`dist/` 顶层只放插件入口**（`emotions.js`/`tts-tool.js`/`tui.js`），CLI→`cli/`、运行时→`runtime/`、
  `lib/**`、`voice/**` 为子目录 ⇒ **`tsc` 产物即发布结构**，本地发布=直接镜像 `dist/`。
- **TUI 编译成 js**：新增 `scripts/build-tui.mjs`，用**宿主同款 Babel 链**
  （`babel-preset-solid` universal(`moduleName=@opentui/solid`) + `@babel/preset-typescript`）把 `src/tui.tsx`
  编译为 `dist/tui.js`（devDeps：`@babel/core`/`@babel/preset-typescript`/`babel-preset-solid`）。
- **package.json**：`main`=`./dist/emotions.js`；`exports`=`{".":"./dist/emotions.js","./tui":"./dist/tui.js"}`；
  `bin.voice-cli`=`./dist/cli/voice-cli.js`；新增 `scripts.publish:proj` 与 `prebuild`（清 `dist/`）。
- **`scripts/publish-proj.mjs`**：清理 `.opencode/plugin/` → **整体镜像** `dist/` → **断言顶层只有插件入口**
  （出现 `voice-cli.js`/`voice-runtime.js` 之类即报错退出）→ 把 `.opencode/tui.json` 的 `plugin` 指向 `./plugin/tui.js`。

### 为什么
- 结构即发布物：省掉「挑拣/改名」这一步易错手工操作，npm 与本地用同一套产物。
- `.opencode/plugin/` **顶层每个 `.js` 都会被 opencode 当 server 插件自动 import**（`config/plugin.ts` 的
  `load()` 以 `{plugin,plugins}/*.{ts,js}` 扫描）——CLI/运行时进子目录后不会被误加载。
- TUI **必须是 Solid 编译产物**：宿主只对 `.tsx`/`.jsx` 施加 `babel-preset-solid`
  （`@opentui/solid` `solid-transform.js` 的 `jsxPattern=/\.[cm]?[jt]sx$/`），对 `.js` 仅重写 import；
  Solid 会把 JSX 包成 `createElement` + `insert(() => …)` + `effect(…setProp)`（响应式），
  而 `tsc` 的 `jsx()` 产物不包裹 props/children ⇒ 槽位失去响应式。故 `.tsx` 不进主 `tsc`。

### 取证（宿主源码）
- `@opentui/solid` `scripts/solid-transform.js:45-56`：`.js` 不施加 Solid/TS preset。
- `@opentui/core` `runtime-plugin.js:3-19,320-345`：把 `@opentui/solid`/`solid-js` 重写为运行时模块 id（含 node_modules ESM）。
- `opencode` `plugin/tui/runtime.ts:47`（`ensureRuntimePluginSupport`）、`plugin/shared.ts:103-114`（npm TUI 需 `exports["./tui"]`）、
  `config/plugin.ts:42-60`（路径相对声明它的配置文件解析）。

### 代价 / 存疑
- `.opencode/plugin/tui.js` 会同时被 server 插件自动发现：server 加载器 `readV1Plugin(..., "server", "detect")`
  对 `{id, tui}` 会抛错（`shared.ts:296-298`），仅被 `plugin/index.ts:224-241` catch 并记日志；非致命但会在日志出现。
- `src/tui.tsx` 仍**不进 `tsc` 类型检查**（`tsconfig` `exclude`），其正确性仅由 Babel 编译 + 宿主运行时验证。
