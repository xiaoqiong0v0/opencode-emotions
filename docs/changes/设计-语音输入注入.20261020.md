# 变更说明：auto-read 派生 bin 根因修复 + 状态目录迁移 + 重启重置 + 槽位 gap 归零（2026-10-20）

对应原文档：`docs/设计-语音输入注入.md` §3 槽位渲染口径、§14.2；`docs/ASYNC.md` 交互点 ⑫⑬与不变量；README「打断 / 自动朗读」。

> 本文件同日多次变更合并，各项以「追加：…」分节顺序排在文末（当前至第八项）。

## 原
- **auto-read 触发了但没声音**：插件日志有 `自动朗读已触发`（spawn 成功后打）却无后续 `tts speak`、无 `tts-playback` 登记、无 warn——
  根因是 `auto-read.ts` 派生 bin 用 `process.execPath`：**server 插件进程里 execPath 是 `opencode.exe`**，
  `opencode.exe <cli.js> speak` 立即失败退出，且 `stdio:"ignore"` 把 stderr 也吞掉，全程静默。
- **状态目录挂在配置目录的临时区**：`<配置目录>/.tmp/data/emotions/` 下放 `auto-tts` / `auto-tts-seen` / `tts-playback` / `tts/`——
  用户判定该目录不对（`.tmp` 语义是可清临时区，状态不该寄生在配置目录下）。
- **重启保留自动朗读开关**：`auto-tts` 文件跨重启存活，重启后 F10 状态延续；用户口径「重启不想保留状态」。

## 现在
- **派生 bin 修复**（`src/voice/auto-read.ts`）：
  - 默认改为 PATH 上的 `node`（env `VOICE_NODE_BIN` 可覆盖，deps `spawnBin` 注入优先级最高）；
  - 子进程 **stderr 接管**（`stdio: ["ignore","ignore","pipe"]`，有界收集）：**非零退出或有 stderr** 时
    `log.warn` 带 `code`/`signal`/`bin` 与 stderr 片段（截 200 字符），不再静默；
  - 主动打断（`interrupt()` kill，`child.killed===true`）不算异常，不刷 warn；
  - `src/cli/emotions-cli.ts:202` 的 `process.execPath` 是 CLI 进程内（=node），**未改**。
- **状态目录迁移**（`src/voice/auto-tts.ts`，全族一次迁完）：
  - 新落点：`~/.opencode/plugins-cache/opencode-emotions/`（`os.homedir()` 拼；对齐先例 `plugins-cache/file-tool`）；
  - 涉及 `auto-tts`、`auto-tts-seen`、`tts-playback`（`playback-state.ts` 经 `autoTtsDataDir` 自动跟随）、`tts/` 临时正文目录；
  - `AutoTtsOptions.configDir` 改为 `dataDir`（状态目录注入，测试隔离用）；`auto-read.ts` 的配置读取单独走 `deps.configDir`；
  - 旧目录遗留文件**不删**（由用户重启后自清），清单见下。
- **重启重置**（`src/tui.tsx` + `resetAutoTtsState()`）：
  - TUI 插件初始化时调用 `resetAutoTtsState()`（`auto-tts.ts` 导出，纯文件删除、幂等）删除 `auto-tts` 与 `auto-tts-seen`——重启 = 自动朗读默认关；
  - 多窗口取舍：**后开的窗口会清掉先开窗口的开关**——已确认接受「重启重置优先」，不做跨窗口保护；
  - `tts-playback` 是播放期瞬态（播完自清），不触碰。

## 为什么
- `opencode.exe <cli.js>` 不是合法的 node 派生方式（opencode.exe 不是 node 运行时宿主），秒退无诊断信息；
  默认 PATH `node` + stderr 接管让失败**可见、可覆盖、可排查**。
- 状态目录应放插件自己的缓存区（`plugins-cache/<短名>`），与 opencode 其它插件一致，不寄生配置目录临时区。
- 用户明确要求重启后自动朗读回到默认关（避免重启后突然又开始朗读）。

## 旧目录遗留清单（不删，由用户自清）
- `<配置目录>/.tmp/data/emotions/auto-tts`
- `<配置目录>/.tmp/data/emotions/auto-tts-seen`
- `<配置目录>/.tmp/data/emotions/tts/`（临时正文目录）
- （`tts-playback` 播完自清，通常不存在）

## 代价 / 存疑
- **多窗口并存**：后开 TUI 窗口会清掉先开窗口的 F10 开关（已确认接受）。
- **旧目录遗留**：迁移不自动搬迁/清理旧文件（按用户口径只列清单不删）。
- **`VOICE_NODE_BIN` 与 TUI 运行时子进程共用同一 env 名**：覆盖会同时影响两者（同为「用哪个 node 跑本插件子进程」语义，视为特性）。
- 真机「触发了但有声音」由用户验证；本批单测覆盖 bin 解析、stderr/非零退出 warn、reset 幂等与新路径断言。

# 追加：槽位指示 `F8 / F9` 被撑出空隙（同日第二项）

对应原文档：`docs/设计-语音输入注入.md` §3「外层 gap 与内层归零」。改动仅 `src/tui.tsx` 槽位返回结构（纯渲染层）。

## 现象
状态条渲染成 `🎙 ● 注入 F8 / F9 🔊 F10`——`F8`、`/`、`F9` 之间各多出一格空隙，与格式串 `formatSlotIndicator()`
（`"🎙 ●  注入 F8/F9 🔊 F10"`）不一致。

## 根因
opencode 宿主 `right` 槽位外层是 `<box flexDirection="row" gap={1} alignItems="center">`
（源码 `packages/tui/src/component/prompt/index.tsx`），**对每个直接子项**接缝各加 1 格 gap。
我方原先返回 Fragment，7 个 `<text>` 被摊平成 7 个直接子项 → 每个接缝 +1 格；而 `F8` / `/` / `F9` 三段自带空格为 0
（`src/voice/slot.ts` 分段数组 + `SLOT_KEY_SEPARATOR="/"`），两个 gap 连续叠在同一接缝，视觉上即 `F8 / F9`。

## 修法
把 7 个 `<text>` 包进**一个内层 `<box flexDirection="row" gap={0} alignItems="center">`**：
对外只占 1 个子项（外层 gap 仅落在整块前后），内部 gap 显式归零 → 各段紧拼，渲染逐字等于格式串（分段内置空格原样保留）。
分段数量、顺序与逐键配色（`F8`/`F9` 各自 `keyActive`/`keyInactive`）**不变**，只加盒子；`src/tui.tsx` 该处注释同步补上
「外层槽位 gap=1、以单内层 box 归零」的因果，并保留原 props 铁律（禁止把访问器函数当 prop 传入，否则 Solid 包成 `Cell` → `ERR_INVALID_ARG_TYPE`）。

## 验证
`npm run build` 通过（Babel 产物确认 `createElement("box")` + `setProp("gap", 0)`）；`npm test` 186/186 全绿——
本改动不进单测（`tui.tsx` 由 Babel 编译、不在 `tsc`/测试覆盖内），故断言零增减，符合纯渲染层预期。真机观感由用户验证。

# 追加：auto-read 增量失效退化整段读（同日第三项）

对应原文档：`docs/设计-语音输入注入.md` §15.3；`docs/ASYNC.md` 交互点 ⑫与不变量。改动 `src/voice/auto-read.ts`、`src/emotions.ts`。

## 现象
F10 开，助手回复**输出完成后**才整段朗读；设计是流式（`tts.streamMinChars` 阈值 + 增量 + 串行队列）。

## 根因（读 opencode v1.18.25 源码取证，非候选①/②原文）
**文本流式的增量不走 `message.part.updated`，走 `message.part.delta`**：
- `processor.ts:499-509`：`text-delta` → `session.updatePartDelta` → 发布 `message.part.delta`，
  payload 只有 `{sessionID, messageID, partID, field:"text", delta}`——**无 part、无类型、无 role**；
- `message.part.updated` 仅在 `text-start`（`text:""`，`processor.ts:496`）与 `text-end`（全量快照，`processor.ts:530`）
  各发一次；reasoning 的 delta 同样走 `message.part.delta`（payload 无类型，无法直接区分）。
- 故旧 `handlePart` 只在 text-end 拿到一次全量文本 → 等价「完成后整段读」。
- 候选①（首块 part 先于 role）**不成立**：助手消息创建即发 `message.updated`（`prompt.ts:1201`），
  早于一切 part/delta；候选②（part.updated 没到插件钩子）**也不成立**：两类事件同一 `events.publish`
  同一总线，`plugin/index.ts:255-262` 全量转发给 `event` 钩子（仅按 `location.directory` 过滤）。

## 修法
- **消费 `message.part.delta`**（新增 `handleDelta()`）：part 类型靠 text-start 快照登记的 `partID→type`
  （`partMeta`）过滤（reasoning/synthetic/ignored 不读）；`message.part.updated` 只作**全量快照校准**
  （不短于已送偏移时以快照为准）。
- **角色惰性补取**：role 未知时经 client 取一次 `info.role`（`fetchMessageRole`，单飞去重；`emotions.ts` 接线）；
  **被角色门挡过事件的 part 置 `tainted`、其 delta 全丢**——不变式：part 的 `text` 恒为真实文本前缀，
  快照 `pending=slice(flushed)` 无重复、无丢失。摘要消息（`summary`）不读。
- **开关读取**：delta 高频路径走 300ms TTL 缓存（`AUTO_TTS_TOGGLE_CACHE_MS`）；`drain` 派生前/
  `part.updated`/完成回退仍实时读（F10「关掉即停」不变）。
- **诊断（长期开，低噪）**：每消息完成时一条 info 汇总
  `自动朗读汇总：message=… path=stream|fallback parts=… deltas=… roleMiss=… skips=… chunks=… chars=…`；
  角色补取另打一条。

## 验证
`npm test` 190/190 全绿（186 基线 + 4 新：delta 流式/reasoning 过滤、角色补取 assistant、角色补取 user、摘要不读；
诊断汇总字段在同一用例断言）；`npm run build`（含 TUI Babel）通过。

# 追加：waveOut 预读缓冲压到 ≈160ms（同日第四项，消 F10 关后 2s 尾音）

对应原文档：`docs/设计-语音输入注入.md` §15.1 播放器；`docs/ASYNC.md` waveOut 不变量。改动仅 `src/voice/tts/stream-player.ts`。

## 现象
F10 关 / 打断杀掉 CLI 后，已排队的音频继续播完（≈2s 尾音）才静音。

## 根因
内置 waveOut（内联 C#）一次性把 PCM 塞满播放队列：`CHUNK=16384B × MAX_PENDING=8` ≈ **128KB ≈ 2.7s**（@24kHz 单声道 16bit）。
CLI 被杀 → 播放器孙进程 stdin EOF，但 EOF 后逻辑是「等已排队缓冲全部播完再退出」→ 长尾音。
（停止红线不变：只按 `tts-playback` 状态文件 PID 杀 CLI；播放器靠 stdin EOF 自退，**禁止** taskkill/按名杀。）

## 修法
**只减队列深度、不减喂入粒度**：块大小改为按时长算 `40ms/块`（≈1.9KB@24kHz，按 `blockAlign` 对齐），
队列深度 `4` 块 → 预读上限 ≈**160ms**（`WAVEOUT_CHUNK_MS`/`WAVEOUT_MAX_PENDING`，JS 侧常量插值进 C#）。
EOF 后最多再播 ≈160ms 即退出；40ms 粒度 + 4 块余量防 stdin 到达抖动欠载断续。
`WAVEOUT_CACHE_KEY` v1→**v2**（内联 C# 变更，避免命中 `%TEMP%` 旧 DLL）。`aplay`/`paplay`/`sox` 天然小缓冲，**不动**。

## 验证
`npm test` 190/190（`stream-player.test.js` 新断言：`maxPending = 4`、块按 40ms 计算、旧 `16384`/`MAX_PENDING = 8` 不得回归）；
`npm run build` 通过。真实「杀 CLI 后 ~150ms 静音」由用户验证（waveOut C# 不进单测）。

# 追加：auto-tts 分会话存储 + 子会话硬跳过（同日第五项）

对应原文档：`docs/设计-语音输入注入.md` §15.3；`docs/ASYNC.md` 交互点 ⑫与不变量；README「热键」「自动朗读」。
改动 `src/voice/auto-tts.ts`、`src/voice/auto-read.ts`、`src/emotions.ts`、`src/tui.tsx`、`src/lib/i18n.ts`。

## 现象（用户实测反馈，两缺陷）
1. `auto-tts` 状态是**全局单文件**（内容 `on`/`off`）：一个会话按 F10 切开关 → **影响其它所有会话/窗口**（用户明确要分会话）；
2. **子会话（subagent 任务会话）也在被自动朗读**（用户明确：子会话不需要自动读）。

## 原
- 状态文件内容为 `on`/`off`（全局一个开关）；`readAutoTts()` / `writeAutoTts(enabled)` 无 sessionID 参数；
- TUI F10 切全局开关；槽位指示器读一次文件作初值、toggle 后同步信号；
- server 侧 `handlePart`/`handleDelta`/`runFallback`/`drain` 读全局开关；无子会话判定。

## 现在
- **分会话 JSON map**：`auto-tts` 内容为 `{ "<sessionID>": true }`（只存开启的会话；缺省=关）。
  `readAutoTts(sessionID)` / `writeAutoTts(sessionID, enabled)`（写为**读-改-写**，保留其它会话条目；原子写）；
  旧格式（`on`/`off`/非法 JSON）**容错为空 map**（不炸）；`resetAutoTtsState()` 保留（删整文件，重启=清全表）。
- **server 侧按消息的 sessionID 查 map**：`handlePart`/`handleDelta`/`runFallback`/`drain` 全部改 `readAutoTts(sessionID, pathOptions)`；
  delta 高频路径的 300ms TTL 缓存改为**按 sessionID 分键**。
- **子会话硬跳过**：
  - deps 新增 `fetchIsChildSession(sessionID)`（`emotions.ts` 经 `client.session.get` 取 SDK `Session.parentID`；
    字段名依据：`@opencode-ai/sdk` `dist/gen/types.gen.d.ts:469` `parentID?: string`；`SessionGetResponses` 200=`Session`，同文件 :1913）；
    auto-read 内部**单飞去重**（`childFetches` Map<string, Promise<void>>）+ **永久缓存**（`childSessions` Map<string, boolean>）。
  - delta/part/drain 走同步 fail-closed 门 `childGateBlocks`：未知期间按「子会话」处理（防子会话首条消息漏读）；
    text-end 快照在判定完成后恢复父会话。
  - fallback 路径 `awaitChildCheck`：**await 单飞判定完成再决策**（避免父会话首条消息在判定未完成时被 fail-closed 误跳过）。
  - 是子会话 → **无论 map 开没开都不读**（early return，`handlePart`/`handleDelta`/`runFallback`/`drain` 全覆盖）。
- **TUI F10 分会话**：切**当前槽位会话**的条目（slot 函数收 `props.session_id`——宿主
  `packages/tui/src/routes/session/index.tsx` 的 `<pluginRuntime.Slot name="session_prompt_right" session_id={route.sessionID} />` 响应式传入）；
  指示器 `autoReadOn` 改为**响应式跟随当前会话**（`autoReadRev` 信号 bump + `readAutoTts(props.session_id)`；切换会话时宿主重算槽位函数）。
  子会话判定用 `api.state.session.get(sessionID)?.parentID` 同步判定（TuiState.session.get 返回本地 `Session`，tui.d.ts:303）；
  是子会话 → toast「子会话不自动朗读」（i18n `autoReadChildSession` zh/en）且**不写 map**。
- **诊断**：每消息汇总日志补 `session=` 与 `skipReason=child`（`自动朗读汇总：message=… session=… path=stream|fallback|skip skipReason=… …`）；
  子会话判定另打一条 `自动朗读子会话判定：session=… child=…`。

## 为什么
- 用户明确要求分会话开关（一个会话的 F10 不应影响其它会话）；
- 子会话是 agent 任务会话，自动朗读会干扰主会话的听感与节奏，用户明确「子会话不需要自动读」。

## 取舍
- **fail-closed vs fail-open**：delta/part/drain 在子会话判定未完成期间按「子会话」跳过（fail-closed）——
  宁可父会话首条消息的 delta 被丢（text-end 快照会兜底恢复），也不让子会话首条消息漏读出去。
  fallback 路径改为 await 判定完成再决策（低频路径，不走 fail-closed，避免父会话首条误跳过）。
- **TUI 子会话判定选了「同步 state + toast 拦截」**（而非降级为「照常切换但服务端硬跳过」）：
  `api.state.session.get(sessionID)` 是宿主本地同步方法，拿到 `Session.parentID` 即可判定，无需经 client 单飞；
  server 侧仍有 `fetchIsChildSession` 硬跳过兜底（TUI 判定失败/绕过时仍不读）。
- **重启仍删整文件**（`resetAutoTtsState`）：用户已定「重启=全关」，分会话 map 也被清空（清全表）。

## 验证
`npm test` **194/194**（基线 190，新增 4：map 格式读写/旧格式容错、按 sessionID 分会话开关 A 开 B 关、
子会话硬跳过 fallback+汇总、子会话增量 fail-closed+父会话恢复；`emotions-cli.test.js` i18n 断言补 `autoReadChildSession`）；
`npm run build`（tsc+Babel）通过。真实多会话/子会话行为由用户验证（需重启 opencode 加载新插件）。

# 追加：F10「灯不变色」——槽位读键与写键不同源（同日第八项）
