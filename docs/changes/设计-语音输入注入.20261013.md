# 变更说明：设计-语音输入注入（2026-10-13）

## 原
- 注入落在 **server 插件** `src/voice-server.ts`：在 `127.0.0.1:8799` 起本地 HTTP 网关
  （`/start`·`/stop`·`/status`·`/inject`），配合 `src/voice/session-tracker.ts`（选最近活跃根会话）
  与 `src/voice/process-manager.ts`（spawn/管理运行时）；TUI 插件 `src/tui.tsx` 轮询 `/status` 并用热键（`ctrl+shift+v`）开关。
- 注入调用按 **v1** SDK 形态：`client.session.prompt({ path: { id }, body: { … } })`。
- 运行时只输出人类可读文本 / `--inject` POST。

## 现在
- **单个 TUI 插件** `src/tui.tsx` 承担全部：UI 指示 + 两热键 + `spawn` 运行时 + 分发 + toast；
  server 插件整套（`voice-server.ts` / `session-tracker.ts` / `process-manager.ts` / `.opencode/plugin/voice-server.js`）删除。
- 两个**点按开关**热键：`F8`=语音注入（`api.client.session.prompt` → 带 `🎙` 标记的新消息），
  `F9`=语音输入（`api.client.tui.appendPrompt` → 增量追加进输入框）；两模式互斥。
- `api.client` 为 **v2** `OpencodeClient`，调用改为**扁平签名**：`session.prompt({ sessionID, parts, noReply })`、
  `tui.appendPrompt({ text })`。
- 运行时新增 `--json`：stdout 只输出 NDJSON 事件（`ready`/`final`/`error`/`done`），人类日志转 stderr；
  共享契约与解析在 `src/voice/ndjson.ts`。

## 为什么
- spike 坐实 TUI 插件自带 `api.client`，注入/写输入框可**一步到位**，无需 server 插件与进程间 HTTP 一跳；
- spike 坐实 `tui.appendPrompt({ text })`（v2 扁平签名）可用 → v1 的 `{ path, body }` 形态不再是 `api.client` 的真实签名；
- spike 坐实长按会键重复、松键不上报 → 只能做点按开关，故用两个独立热键而非「按住说话」。

## 追加（同日）：语音输出（`speak` 工具）

- **新增**：server 插件 `src/tts-tool.ts`（`{ id:"tts-tool", server }`）注册 `speak` 工具；provider 抽象 `src/voice/tts/`（`types.ts` / `sapi.ts` / `aliyun.ts` / `index.ts`），默认本机 Windows SAPI，`aliyun` 占位。
- **为什么需要 server 插件**：`tui.d.ts:509` 的 `TuiPluginModule` 有 `server?: never`，TUI 插件不能注册工具——与上文的「单个 TUI 插件」并非冲突（那是语音**输入**注入，走 `api.client`；工具注册只能由 server 插件提供）。
- 配置 `TTS_PROVIDER`/`TTS_VOICE`/`TTS_RATE`；`execute` 后台播放并立即返回字符串；并发/打断见 `docs/ASYNC.md` 交互点 ⑨。


## 追加（同日）：配置化 + 双协议 ASR + 多语言

- **原**：设备名、模型、`language:"zh"`、VAD（含 `prefix_padding_ms`）写死在 `src/voice/aliyun.ts`；TTS 只认环境变量。
- **现在**：
  - 新增 `<配置目录>/voice.jsonc`（目录 = `~/.config/opencode`），首次缺失自动写带注释默认，读取失败静默降级；环境变量可覆盖。配置项：`device` / `asr.{provider,model,language}` / `vad.{threshold,silenceDurationMs}` / `tts.{provider,voice,rate}`。
  - `asr.provider` 预设：`aliyun-qwen`（realtime 协议，16k/7 类情绪）/ `aliyun-8k`（inference，8k/3 类）/ `aliyun-v2`（inference，16k/无情绪）；`AliyunAsrClient` 泛化为双协议。
  - **删除 `prefix_padding_ms`**（阿里云无此参数，原实现无效）；`vad.threshold` 默认由文档 0.2 调到 **0.5** 抗噪。
  - `asr.language` 默认空 = 自动识别（多语言），不再写死 `zh`。
  - 新增零依赖 `src/lib/config-dir.ts` / `src/lib/jsonc.ts`（等价移植参考实现，不 import 配置仓文件）。
- **为什么**：参数写死无法按机器/场景调整；抗噪只能靠 VAD（阿里云无独立降噪参数）；多语言需去掉语言硬编码。
- **不做文字过滤**（上一轮思路作废）。


## 追加（同日）：凭证可配 + ASR 语种/语料 + CosyVoice TTS

### 原
- 凭证路径写死在 `src/voice-runtime.ts`（`<cwd>/.tmp/aliyun`），仅 `--credentials` / `ALIYUN_CREDENTIALS` 可改。
- `asr` 只有 `provider`/`model`/`language`，无热词表/语言提示/上下文。
- `tts.aliyun` 是空占位（`speak` 直接抛「尚未实现」）；TTS 仅 `provider`/`voice`/`rate`。

### 现在
- 新增 `src/voice/credentials.ts`：`resolveCredentials` 优先级 **环境变量（`DASHSCOPE_API_KEY`/`DASHSCOPE_WORKSPACE_ID`）> 配置 `asr.credentials.apiKey`/`workspaceId` > 凭证文件（`path`，1 行 workspaceid/2 行 apikey）> 默认 `<cwd>/.tmp/aliyun`**；文件路径 `--credentials` > `VOICE_ALIYUN_CREDENTIALS`(兼容 `ALIYUN_CREDENTIALS`) > `path` > 默认。`loadCredentials`/`redact` 迁入本模块（`aliyun.ts` 再导出兼容）。
- `asr` 新增 `languageHints[]`/`vocabularyId`/`context`/`credentials`；`resolveAsrParams` 按 provider 能力过滤（`aliyun-8k`/`aliyun-v2` 支持前两者，`context` 当前无 provider 支持），被忽略项记日志不报错。
- `tts` 新增 `instruction`/`pitch`/`volume`/`format`/`sampleRate`/`model`；`src/voice/tts/aliyun.ts` 由占位改为 **CosyVoice WebSocket** provider（默认模型 `cosyvoice-v2`、音色 `longxiaochun_v2`——自测发现 `longanyang` 属 v3 会报 418，播放仅 Windows，合成结果落临时 WAV 用 SoundPlayer）；`ignoredTtsParams` 过滤 sapi 不支持项。
- 新增 `src/voice/ffmpeg.ts`（`resolveFfmpegPath` 从 `capture.ts` 抽出 + `decodeToWav`），供采集与云 TTS 播放复用。

### 为什么
- 凭证写死无法按机器/场景切换；明文只应存在于文件/环境变量，且绝不打印。
- 领域准确率需按模型能力提供热词/语言提示；qwen3-asr-flash-realtime 不支持热词/上下文，必须显式忽略而非报错。
- CosyVoice 提供方言/情感/角色风格指令与语速/音高，是 TTS 风格化的官方路径。
