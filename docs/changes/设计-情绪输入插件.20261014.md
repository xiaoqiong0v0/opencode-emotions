# 变更说明：移除手动符号解析，仅保留情绪命令（2026-10-14）

对应原文档：`docs/设计-情绪输入插件.md`（标题由 v0.2「符号 + 命令」改为 v0.3「命令-only」）。
同步口径：`docs/设计-语音输入注入.md` §1 / §8。

## 原

- 插件有**两种**手动输入方式：**符号**（开头/结尾的 `!`/`?`/`...`/`。。。`/`666` 连续串）与**命令**（`/angry` 等）。
- `src/emotions.ts` 的 `chat.message` 钩子调 `rewriteEmotion()`，把消息文本**就地改写**为 `emoji(等级/3) + 正文`。
- `src/lib/parser.ts` 导出符号解析全家桶：`parseEmotion` / `rewriteEmotion` / `ANNOTATED_PREFIX_RE`，及内部符号表（`SYMBOL_CHARS` / `MIN_COUNT` / `OPENING_RULES` / `CLOSING_RULES` / `parseOpening` / `parseClosing` / `levelOf` 等）。

## 现在

- **符号解析整体删除**，只保留命令：
  - `src/lib/parser.ts` 仅保留 `trimAnnotationTail`（及内部 `ANNOTATED_PREFIX_RE`）；**删除** `parseEmotion`、`rewriteEmotion`、`ParseResult`、全部符号表与匹配函数（`ANNOTATED_PREFIX_RE` 不再导出，无外部引用）。
  - `src/emotions.ts` 的 `chat.message` **不再改写消息语义**，只对「以情绪标注开头」的文本清理尾部空白（无参数命令模板空参替换残留的尾随空格）；`config` 注册命令不变 ⇒ **命令照旧可用**。
  - `test/parser.test.js`：符号解析用例（`REWRITE_CASES` / `NO_MATCH_CASES` / 幂等 / `parseEmotion`）全部删除；命令模板与 `trimAnnotationTail` 用例保留。
- 设计文档就地改：删除「符号表 / 解析规则 / 符号相关限制」等章节，改为命令-only 口径（`docs/设计-情绪输入插件.md`）。

## 为什么

- **冗余**：语音来源（TUI 插件）已自动产出同一套 `emoji(等级/3)` 标注，手动符号是通往同一结果的第二条路径。
- **有误伤、有硬限制**：`? 这是什么`、`666 元` 无法与有意表达情绪 100% 区分；行首半角 `!` 被 opencode shell 模式拦截、到不了插件。命令显式、零歧义，是更可控的手动兜底。
- 情绪模型层（`src/lib/emotions.ts`）不变 ⇒ 标注格式与命令行为零变化，仅**删除**一条输入路径，不引入迁移成本。

## 影响 / 代价

- 行为变化：用户不能再靠 `!!!` / `？？？` / `...` / `666` 触发标注（**破坏性变更**，面向 npm 首发随 0.1.0 一并说明）。
- `src/lib/parser.ts` 文件名沿用（现内容与「解析」无关，仅承载标注文本工具），未改动引用方路径。
