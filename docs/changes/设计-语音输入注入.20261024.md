# 变更说明：设计-语音输入注入（2026-10-24）

对应文档：`docs/设计-语音输入注入.md` §17.2 / §17.6；同步 `docs/ASYNC.md` 按段 ASR 不变量、`README.md` 的 `vad.threshold` 说明。

## 原

- **VAD 标定**：`vad.threshold` 单调映射为**固定** dBFS 短帧门（默认 0.5 → -35 dBFS）。依据是「本机静音底噪 RMS 0.00035~0.00061（≈ -69~-64 dBFS）」，认为 -35 dBFS 既能收下 0.035 平均 RMS 的语声、又能挡住底噪。
- **单段上限**：`DEFAULT_MAX_SEGMENT_MS = 60000`（60s）。
- **停止后的 final**：`dispatch()` 只按**当前** `injectOn()`/`inputOn()` 分叉；按 F8/F9 关闭后 runtime 冲刷出的最后一段 final 既不注入也不追加，**且无日志**（静默丢弃）。

## 现在

- **VAD 底噪自适应**：实际门限 = `clamp(max(thresholdToDbfs(配置), noiseDbfs + 6dB), -50, -20)`。
  - 余量取 **6dB**（原 8dB）：30ms 帧级实测底噪 p10=-32.9 / p99=-27.6 / max=-25.6 dBFS、正常语声 p50=-16.8 / p90=-12.1 dBFS（SNR≈15dB），8dB 下噪声误判 0%、语音命中 72%，6dB 下误判 0.6%、命中 81%。
  - **语音确认**：必须**连续 5 帧（`VOICE_CONFIRM_FRAMES=5`，5×30ms=150ms）**都 ≥ 门限才把 `hasVoice` 置真，单帧/孤立尖峰不算、低于门限的帧把连续计数清零；确认期的帧仍留在缓冲里（不丢句首 150ms），`silenceMs` 只统计置真之后的静音。
  - 起录用前 500ms 的 30ms 帧 RMS(dBFS) 取 **20% 低分位**作 `noiseDbfs` 初值；预热帧按新门限**重放**（**已被同日 2026-10-25 修订取代，见文末「同日修订」**）。
  - 运行中「**只降不升**」：连续 3 帧都比当前底噪低 ≥3 dB 才确认下移、单次最多降 6 dB（防止 1~2 帧偶发低谷把门限拉塌）；**高于底噪的帧一律不改底噪（不自动上移）**——同日实测发现原「慢升」会覆盖语声，见下文「为什么」（**该口径已被同日 2026-10-25 修订取代，见文末**）。
  - 门限变化 ≥3 dB 才写一行 `asr gate:` info 日志（旧/新门限 + 底噪估计）。
  - 切段判据不变：`hasVoice && silenceMs >= silenceDurationMs`；纯静音段仍不发送。
- **单段上限**：`DEFAULT_MAX_SEGMENT_MS = 12000`（12s）。
- **停止后宽限投递**：模式关闭时先记录「模式 + 会话 id + 时刻」再 `stopRuntime()`，停止返回后刷新时刻；`dispatch()` 在静音门之后按 ① 当前开关 → ② 会话一致且（**停止进行中** 或 关闭后 ≤ `STOP_FINAL_GRACE_MS`(3s)）则按关闭前模式投递 → ③ 否则丢弃并写 `asr final drop:` info 日志（reason/session/模式/ageMs/前 20 字文本预览）。会话一致复用无主哨兵口径（`sessionID ?? PLAYBACK_OWNERLESS_KEY`），不跨会话匹配。

## 为什么

- **旧标定被一手实测推翻**：本机麦克风底噪 RMS 实测 **0.03~0.05（≈ -30~-26 dBFS）**，**高于固定门限 -35 dBFS** ⇒ 每帧都判「有语音」、`silenceMs` 恒 0，说话过程中永不切段（只能等 60s 上限或停止冲刷）；静音段还会被送 ASR 产生幻听文本。固定门限无法适配不同麦克风/增益，故改为按底噪自适应。
- **底噪取消自动上移（同日实测，推翻首版「慢升」）**：首版每帧最多上移 0.05 dB（≈1.6 dB/s），用户持续说话时把语声当成新底噪，门限 20s 内从 -35 漂到 -25.9 dBFS（实测日志 `asr gate: reason=tracked noiseDbfs=-31.9 oldGateDbfs=-28.9 newGateDbfs=-25.9`），最终盖住语声、一个段都检不出。语声是短时起伏而非环境底噪，故底噪**只降不升**；环境变吵的少量误判由 150ms 连续确认挡住。回归用例断言 20s 语声期间门限只降不升。
- **余量 8→6dB + 150ms 连续确认**：8dB 余量在本机实测下把句首轻音/气声切掉太多（语音命中仅 72%）；降到 6dB 命中升到 81%，代价是误判从 0% 升到 0.6%——用「连续 5 帧越门限才算语音」把偶发噪声尖峰挡回去，同时不丢句首（确认期帧仍入缓冲）。
- **60s 兜底太长**：底噪误判或连续说话时，首个结果要等一分钟；12s 在「单次请求延迟」与「不断句成本」之间更合理，且仍远低于云端 5 分钟上限。
- **停止后的 final 静默丢弃是真实缺陷**：`runtime` 优雅停止本就是「先冲刷最后一段并等 ASR 回包」，此时模式已 off；不保留关闭前模式就必然丢最后一句，且无日志无从排查。3s 宽限覆盖优雅停止的常见耗时，又不会把很久以后的迟到结果误投到已关闭的模式。

## 同日其它变更（合并记录）

### ① Linux 默认输入源改为 `pactl get-default-source`

- **原**：Linux 未显式指定设备时按 `pactl list short sources` 的枚举顺序取第一条（可能是 `.monitor` 回环源）；pulse 启动失败回退 alsa 时仍把 pulse source 名传给 `-f alsa`。
- **现**：优先 `pactl get-default-source`（空/失败/占位符 `@DEFAULT_SOURCE@` 视为无）；否则取枚举中**非 `.monitor` 的真实输入源**第一条；pactl 只有 monitor 时再用 `arecord -l` 找硬件设备；`--list` 把系统默认源置顶。pulse→alsa 回退只把 pulse source 名换算为 `default`，已是 ALSA 设备名（`hw:`/`plughw:`/`CARD=`/`DEV=` 等）则原样保留。
- **为什么**：避免默认落到 monitor 回环（采集到扬声器输出而非麦克风），也避免把 pulse source 名当 ALSA 设备名导致回退失败。

### ② 双宽 emoji 右半格底色错乱登记为宿主已知问题（设计文档 §24）

- **原**：`🎙️`/`🔊` 的右半格底色与左半格不一致，疑为插件配色/渲染问题。
- **现**：定位为宿主 opentui 的 continuation cell 背景继承/下发缺陷（上游 PR #791、issue #1654 对应），插件源码无 `backgroundColor`/`bg` 写入、无法在插件侧修复；已按用户决定「先忽略、记录」登记在 `docs/设计-语音输入注入.md` §24，不改插件配色/字形（§3 的 emoji 风格与 18 列宽度契约保持不变）。
- **为什么**：避免把宿主缺陷当插件 bug 反复改配色，同时留下取证与复验点（等宿主升级/上游修复后复验）。

## 影响 / 代价

- 门限行为随底噪变化：安静环境仍回落到配置基线（不降低灵敏度）；高底噪环境门限升高，**低于「底噪+6dB」的轻声可能不被判为语音**（这是挡住底噪、避免幻听的必要代价）。
- 语音确认要多等 150ms 才置「有语音」：句首 150ms 不丢（仍在段内），但**短于 150ms 的孤立爆破音/音节可能不被当语音**；配合 6dB 余量换来更低误判（语音命中 72%→81%）。
- 单段最长从 60s 缩到 12s：连续说话会被切成更多段，每段一次 HTTP（结果总数增加、单条延迟下降）。
- 停止进行中到达的 final 始终按关闭前模式投递；停止结束后 3s 内到达的 final 仍会投递（用户可能已切走焦点）；更晚的丢弃并留日志。
- 测试：`test/asr-segment.test.js` 新增/更新底噪自适应、语音确认（单帧尖峰/仅 4 帧不提交、连续 150ms 提交且段内含句首 150ms、确认前静音不提前切段）与 12s 兜底用例，并把余量相关期望值改为 6dB；`test/asr-gate.test.js` 新增 `resolveFinalDelivery` 宽限决策用例；`test/tui-diagnostics.test.js` 新增产物接线断言。

## 同日修订（2026-10-25）：底噪估计改为 5s p10 滑动分位

- **原来（本文上半部分的底噪口径，已作废）**：起录前 500ms 低分位**一次性标定** + 运行中「**只降不升**」跟踪。
- **现在**：维护最近 **5s**（`NOISE_WINDOW_MS=5000`，167 个 30ms 帧）的 dBFS 环形缓冲，`noiseDbfs` 取 **p10**（`NOISE_WINDOW_PERCENTILE=0.1`）；有效帧数 <**1s**（34 帧）时 `noiseDbfs=null`、退回 `thresholdToDbfs(配置)`；每 **10 帧（300ms）**重算一次，不逐帧排序；门限 `clamp(max(基线, noiseDbfs+vad.marginDb), -50, -20)`；门限一次上抬 **≥3dB** 时重置当前段 `hasVoice`/`voiceStreak`/`silenceMs`（缓冲保留，不做逐帧重放）。日志 `asr gate: reason=windowed` 与 `[vad]` 诊断行保留；`VOICE_CONFIRM_FRAMES=5`（150ms）、12s 兜底、切段/结果日志不变。
- **为什么**（2026-10-25 14:30 一手实测，`~/.opencode/plugins-log/20261025.log:30-37`）：冷启动瞬间是**数字静音**（`[vad] noise=-73.4`），一次性标定把它锁死，「只降不升」又让它永远升不回真实环境底噪（≈**-32**）⇒ 门限停在 **-35**（比真实底噪还低）⇒ 噪声帧全被判「有语音」⇒ `silenceMs` 恒 0 ⇒ **停顿切段永不成立**（只能靠 12s 兜底，日志 `[asr] segment submit dur=12.0s`）。同期用户语声 p50=-16.9 / p90=-6.1 / max=-4.1 dBFS（SNR 足够），ASR 结果本身正确。滑动 p10 同时满足两点：冷启动偏低 **5s 内自愈**；说话期间 p10 仍贴底噪、不被语声 p50 带跑。
- **测试（真断言）**：`test/asr-segment.test.js` 新增/改写——冷启动数字静音 → 真实底噪 -32：5s 内门限升到 -26±1.5（并断言 `reason=windowed` 日志）；稳态 -32 门限稳定 -26±1（波动 <2dB）；连续 20s 语声（p50 -17）门限不抬到 -20 以上；低 SNR 语声（比底噪高 7dB）150ms 确认后切段；少量低谷帧不入 p10；保留单帧尖峰不提交、150ms 确认、暂停切段、12s 兜底。
- **影响 / 代价**：环境变吵后门限约 5s 才完全跟到新底噪（期间可能多判少量噪声，由 150ms 确认与上抬保护兜底）；窗口内真实底噪若长时间缺席（持续说话 >90% 帧），p10 会偏向语声轻音并抬高门限，最终由 [-20] 上界兜住，轻语声可能漏判句首（150ms 确认会重新捕获）。
