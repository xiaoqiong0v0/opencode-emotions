# 变更说明：语音运行时脚本改按**插件产物自身位置**解析（2026-10-22）

对应原文档：`docs/设计-语音输入注入.md` §4 运行时 / §5 时序；`docs/ASYNC.md` 交互点 ⑥与不变量「至多一个存活子进程」段；`README.md`「产物镜像」段。
改动 `src/tui.tsx`、新增 `src/lib/runtime-diagnostics.ts`、新增 `test/runtime-diagnostics.test.js`、补 `test/tui-diagnostics.test.js` 产物锚点断言。

## 现象（用户实测）
在家目录 `C:\Users\king-\` 启动 opencode，按 F8/F9 起不来，toast：
`语音运行时已退出（code=1 signal=-）；stderr：Node.js v24.16.0`。
日志：`mode started` 后约 1s `childAlive=false`。

## 根因
`src/tui.tsx` 旧代码 `const script = process.env[SCRIPT_ENV] || resolve(process.cwd(), ...RUNTIME_SCRIPT)`
——运行时脚本按 **cwd 相对**拼。插件产物在 `~/.cache/opencode/packages/.../dist/`，cwd 却是用户启动目录
⇒ 拼出 `C:\Users\king-\dist\runtime\voice-runtime.js`（实测不存在）⇒ spawn 的 node `Cannot find module` 立即退出。
次生问题：stderr 只留**末行**，而 Node 崩溃输出末行是版本横幅 ⇒ 提示里只剩 `Node.js v24.16.0`，看不出原因。

## 原来 → 现在
- **脚本路径口径**：原来 `VOICE_RUNTIME_SCRIPT` > `<cwd>/dist/runtime/voice-runtime.js`（唯一口径）。
  现在 `VOICE_RUNTIME_SCRIPT`（显式覆盖，最优先，相对值按 cwd 归一）> **插件产物自身位置**
  （`SELF_DIR = selfDirFromModuleUrl(import.meta.url)` → 同级 `runtime/voice-runtime.js`）> cwd 拼法（**仅兜底**，
  日志以 `scriptSource=cwd` 显式标注）。`dist/` 与镜像后 `.opencode/plugin/` 两种布局同构，同一锚点都命中。
  - 锚点选择依据：TUI 产物是 ESM，`scripts/build-tui.mjs` 的 Babel 链（`babel-preset-solid` + `preset-typescript`，
    无模块转换预设）**原样保留 `import.meta.url`**（已实测：`dist/tui.js:97` 存在该表达式，且有产物文本断言防回归）。
    宿主若把模块 URL 虚拟化（非 `file:` / 非绝对路径），`selfDirFromModuleUrl` 返回 `null` ⇒ 自动降级兜底并记日志。
- **不再依赖 cwd，也不静默**：候选都不存在 ⇒ `startRuntime()` 在 spawn **之前**抛错，错误与 `startRuntime begin`
  日志都带**完整绝对路径 + 来源 + 全部候选**（`scriptSource=` / `scriptExists=` / `selfDir=` / `candidates=`）。
- **stderr 口径**：原来 toast 显末行（截 24 字符）。现在 toast 显**关键行**（`pickStderrSummary`：优先含错误标记的行
  → 首个非噪声行 → 首行，截 120 字符），进程内 `stderrTail` 留末尾 4000 字符、折叠换行进 `runtime exited:` /
  `startRuntime failed:` 日志（全量可还原）。
- **影响面**：`VOICE_RUNTIME_SCRIPT` 语义不变（仍最高优先）；未设该 env 的用户由「cwd 口径」改「产物口径」——
  属修复，无需迁移。旧常量 `RUNTIME_SCRIPT`（cwd 路径段）移入 `lib/runtime-diagnostics.ts` 的
  `RUNTIME_RELATIVE_TO_CWD`，`tui.tsx` 不再自行拼路径。

## 验证
- 新增/补强单测 15 例（247 → 262，全绿）：路径解析四态（env/self/cwd/none）、镜像布局、锚点不可靠降级、
  stderr 关键行与截断；`test/tui-diagnostics.test.js` 断言产物含锚点且旧 cwd 拼法不复活。
- 静态端到端探针（cwd 设为家目录复现根因）：解析得 `<repo>/dist/runtime/voice-runtime.js`，
  `source=self exists=true`；旧口径 `<home>/dist/runtime/voice-runtime.js` 实测不存在。
- 待真机确认（由用户）：重启 opencode 后在家目录按 F8/F9，日志应出现 `startRuntime begin: … scriptSource=self`。

# 追加（同日第六批）：会话级中断请求水位 `interrupt-req`——修「按 F10 中断后剩余文本继续播」

对应原文档：`docs/设计-语音输入注入.md` §14.2（共享状态清单）、§15.2（触发点③/新增「会话级中断请求水位」条/F8·F9 正确性链路的**边界收窄**）、§15.3（新增「打断的第二条入口」）、§16.4（门释放姿势）；`docs/ASYNC.md` 并发边界清单增 ⑰、交互点新增 ⑰、不变量新增「会话级中断请求水位」。
改动 `src/voice/auto-tts.ts`（`INTERRUPT_REQ_FILE_NAME`/`autoTtsInterruptPath`/`writeInterruptRequest`/`readInterruptRequest`）、`src/tui.tsx`（两处中断出口写水位）、`src/voice/auto-read.ts`（`messageStarts` 记账 + `stopInFlight` 抽取 + `applyInterruptRequest` 消费）；测试 `test/auto-tts.test.js` +8、`test/tui-diagnostics.test.js` +1。

- **现象（用户实测）**：按 F10 中断播放后，**有时**剩余文本继续播、有时正常。
- **根因（不是概率，是结构缺口）**：F10 的中断动作只有 `stopPlayback({ sessionID })`（按 `tts-playback` 里的 PID 杀进程），而服务端 auto-read 对「用户按了中断」**一无所知**。两个缺口：① **杀空**——按键落在两个朗读单元之间（上一句已播完、下一句还没投递），此刻没有登记在册的播放进程，`stopPlayback` 无事可杀，队列里的下一句照旧 `spawn`；② **杀后重生**——follow worker 被杀后该消息改走 `deliverUnit` 的**非 follow 分支**重新 `spawn` CLI。§15.2 原结论「F8/F9 中断链路真实存在、**无缺口**」只覆盖「已有进程被杀中且后续确实写失败」这一条，本批**收窄该结论**并补上兜底（链路本身未改）。
- **原来 → 现在**：原来中断意图只活在 TUI 那一次 `stopPlayback` 调用里；现在**先原子写** `<会话目录>/interrupt-req`（内容=请求时刻）**再** `stopPlayback`——写序保证停播抛异常时意图也已落盘。消费端在**每个派发单元前同步读一次、不加缓存**（`deliverUnit` 入口=follow 写前=非 follow spawn 前的唯一派生入口；`runFallback` 整段读前补一处），要的正是新鲜度（单元间隔秒级）。
- **命中语义（钉死）**：请求时刻**严格大于**该消息开始时间 ⇒ 命中 ⇒ 走与 `interrupt()` **同一套**打断执行体（`interrupt()` 的函数体抽成 `stopInFlight(sessionID?, startedBefore?)`，`interrupt` 只是不带时间上限的调用——**没有第二份水位/清队列/杀进程代码**）：置 `interrupted` 水位＋清队列/carry＋按归属只 kill 本会话且开始早于水位的子进程。水位是**会话级时间戳**不是布尔 ⇒ 晚于水位的**新**消息不受影响（F10 双态只停声、开关没变 ⇒ 后续回复照读）；**相等不算命中**。
- **开始时间从哪来**：新增 `messageStarts`（`messageID→开始时间`，上限 `MESSAGE_START_LIMIT`=200）——优先服务端 `info.time.created`（权威、早于插件观察，晚到事件可覆盖），否则 `diagFor` 建计数条目时的首次观察时刻。**无记账 / 读失败 / 缺文件 / 内容非法**一律**放行**（宁可漏拦不可误杀，绝不影响热键与朗读主链）。
- **不改**：F10 双态语义（中断分支**不写**开关文件、不 bump 指示灯）、i18n toast、runtime、CLI、`playback-state` 的 `stopPlayback` 本身。F8/F9 写水位带「取到会话路由才写」门（取不到不写，保持无主语义）；F10「关闭」分支仍只写开关文件（`drain` 派生前实时复查已覆盖），**不**写水位。
- **清理口径**：`interrupt-req` 在**会话目录内** ⇒ 随 `resetAutoTtsSession()`/`resetAutoTtsState()` 整目录删除一起清；**不进** `AUTO_TTS_RESET_KEEP_NAMES`（那个清单只管 base 根的 `tts-playback`/`tts`，误加会把水位文件当保留项留下）。
- **残余（已知、不掩盖）**：已递给 worker/CLI 的**当前单元**不追回（靠 `stopPlayback` 双 PID 静音），生效延迟只到下一个单元；插件从未观察到的消息无开始时间记账 ⇒ 不被水位命中（与交互点 ⑫ 的既有残余同源）。
