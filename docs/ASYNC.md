# 异步交互点清单（ASYNC）

> 登记「代码里一眼看不出的」并发契约：共享状态 · 保护手段 · 顺序契约 · 失败/取消/超时。
> 维护：新增异步 ⇒ 同批加行；改动异步 ⇒ 同步改对应行；删除 ⇒ 同步删。

## 一、并发概览

| 项 | 内容 |
|---|---|
| 并发模型 | 单线程事件循环（Node / Bun）；并发来自子进程 stdout 事件、WebSocket 回调、定时器、宿主热键回调 |
| 并发边界清单 | ① ffmpeg 采集 stdout → ASR 喂流；② WS 收消息 vs `finish()` 等待；③ WAV 自测的节奏定时器；④ 采集统计定时器；⑤ SIGINT 收尾；⑥ **TUI 插件**：子进程生命周期 vs 热键开关；⑦ TUI：stdout 事件回调 vs 分发（**含半双工静音门**：`dispatch()` 只读 `tts-playback` 判活，活跃即丢 final）；⑧ TUI：并发 dispatch（连续 final）；⑨ **TTS**：工具 → CLI 前台 → 分离 `__play` 播放进程；⑩ **TTS**：CosyVoice **流式**合成 / AudioSink vs 连续 `speak` / 取消；⑪ **TTS CLI**：`exec` 前台与分离 `__play` 的进程边界；⑫ **自动朗读**：`event` 钩子（增量 vs 完成） vs 状态/去重文件 vs 派生 CLI 子进程 vs 打断；⑬ **打断（barge-in）**：跨进程按 PID 停止播放（共享状态文件）；⑭ **TTS**：MiMo SSE **流式**合成 / AudioSink vs 连续 `speak` / abort；⑮ **ASR 按段**：采集回调缓冲 vs 串行 HTTP drain vs `close()` abort；⑯ **自动朗读 follow worker**：`speak --follow` 常驻子进程（stdin 行流 vs 句块投递 vs EOF 收尾 vs 天折停读）；⑰ **会话级中断请求水位**：TUI 进程原子写 `interrupt-req`（请求时刻）vs auto-read 每派发单元同步读并按消息开始时间收窄（杀空/杀后重生的跨进程兜底）；⑱ **电平事件跨进程上行**：runtime 采集电平定时器（10Hz 节流、写 stdout）vs TUI `micLevel` 信号（直接覆盖、可丢帧，**不代表可靠送达**）; ⑲ **自动朗读首句合并窗**：首句就绪后等自适应合并窗（基值 400ms、按观测句间间隔放宽、上限 1200ms；`setTimeout` + 50ms 轮询）vs 派发 vs 下一条到达/`finalize`/打断唤醒; ⑳ **自动朗读预取**：播第 N 句期间合成第 N+1 句（`--pcm-out` 落盘）+ 预热播放进程（`--pcm-file --pcm-follow`，预热在 `go` 之前）vs 上一单元退出后写 `go` 交播（**播已到达部分、由播放子进程按 `stat` 长度跟随读文件**，写端 `done`/`abort` EOF 收尾）vs `interrupt`/`interrupt-req` 取消（kill + 删文件）vs 写端异常退出码 3（已播部分，不重读）; ㉑ **runtime 停止通道**：TUI 经子进程 stdin 写 `stop` 行/EOF（win32 无法捕获 SIGTERM，优雅停止只走 stdin）vs `createStopController()` 幂等收敛（SIGINT/SIGTERM/SIGBREAK + `--seconds` 任一先到即 `finish()`）vs `stopRuntime()` 10s kill 兜底; ㉒ **ffmpeg 运行时自愈**：`ensureFfmpegBinary()` 的 `install.js` 子进程（默认 120s 超时、超时 kill）vs 运行时「先自愈、后枚举设备」的启动顺序（每进程一次 memo；失败即终止启动，不并发枚举）; ㉓ **Linux 采集回退**：ffmpeg `-f pulse` 子进程启动失败（spawn error 或 3s 内 0 字节 + 连接/设备类错误）→ 自动改试 `-f alsa` **一次**（绝不循环；有音频/已回退/停止中不回退） |
| 守护措施 | `docs/ASYNC.md` + 技能门禁脚本 `check_async_inventory.py`（改了异步代码必须同批改本清单） |

- **电平事件是「最新值」语义、不代表可靠送达（2026-10-22 第十三批）**：runtime 采集期间最多每 `LEVEL_EVENT_INTERVAL_MS`(100ms) 发一条 `level`（10Hz 节流），写失败/未 flush **丢这一帧、不重试不抛错**；TUI 收到即**直接覆盖** `micLevel`（不累积、不排队），丢帧只表现为音量列少一次刷新。`level` 只在采集激活期间发（`waitForStop` 返回即停表）⇒ `done` 之后不再有电平；非法电平（非有限数值）由 `parseEventLine` 丢弃整条事件，越界值由渲染端 `meterGlyph` clamp。
- **会话级中断请求水位（`interrupt-req`，2026-10-22，修「按 F10 中断后剩余文本继续播」）**：`stopPlayback` 按 PID 杀，结构上有两个拦不住的缺口——**单元间隙没有进程可杀（杀空）** 与 **worker 死后 auto-read 重新 spawn（杀后重生）**；故中断意图必须跨进程落文件：TUI 的两个中断出口（F10 双态中断分支、F8/F9 `toggleMode` barge-in）**先原子写** `<root>/<sessionID>/interrupt-req`（内容=请求时刻）**再** `stopPlayback`，server 侧 auto-read 在**每个派发单元前**同步读（`deliverUnit` 入口＋`runFallback` 整段读前，**不加缓存**要的就是新鲜度），请求时刻**严格大于**该消息开始时间 ⇒ 命中，走与 `interrupt()` **同一套**打断执行体 `stopInFlight(sessionID, 请求时刻)`（置 `interrupted` 水位＋清队列/carry＋只 kill 本会话且在水位之前开始的子进程）。**口径钉死**：① 水位是**会话级时间戳**，不是布尔——所有「开始时刻 &lt; 请求时刻」的在途消息都停，**晚于水位的新消息不受影响**（F10 双态只停声、开关没变⇒后续回复照常读）；相等不算命中（严格大于）；② 开始时间取**服务端 `info.time.created`**（权威，晚到事件可覆盖插件首观察值），无记账（插件从未收到该消息任何事件）⇒ 按当前时刻算＝视作刚开始 ⇒ **放行**；③ 读失败/缺文件/内容非法一律读 `0` **放行**（宁可漏拦不可误杀）；④ 取不到会话路由**不写**（保持「无主」语义）；⑤ 该文件在**会话目录内**，随 `resetAutoTtsSession()` 整目录删除一起清，**不得**进 `AUTO_TTS_RESET_KEEP_NAMES`（那只管 base 根的 `tts-playback`/`tts`）；⑥ 不改 F10 双态语义/i18n toast/runtime/CLI/`stopPlayback` 本身。残余：已递给 worker/CLI 的当前单元不追回（由 `stopPlayback` 双 PID 静音），生效延迟只到下一个单元。
