# 语音输入 + 情绪 → 注入 opencode 设计（v0.3，单 TUI 插件）

> 状态：待评审 ｜ 日期：2026-10-13
> **硬约束：全链路 TypeScript / Node，不依赖 Python**（不是每台机器都装了 Python）。
> v0.1（含 Python 采集侧）与 v0.2（server 插件 + HTTP 网关 + session-tracker + process-manager）作废；
> 改为**单个 TUI 插件**（`src/tui.tsx`）承担全部：UI + 热键 + 运行时管理 + 分发。

## 1. 目标

- 说一句话 → 转写 + 情绪识别 → **注入当前 opencode 会话**（等同用户发了一条消息）
- 情绪归一为既有标注 **`emoji(等级/3)`**（与手动来源统一）
- **去掉手动符号解析**（`!`/`?`/`...`/`...`/`666`），**保留命令**（`/angry` 等）作手动兜底
- 提供一个**可交互的 UI**：开始/停止连续语音、看到状态、可切换会话

## 2. UI 能力调研（关键结论）

opencode **有一套 TUI 插件系统**（`@opencode-ai/plugin/tui`，本机 `dist/tui.d.ts` 取证），**但官方文档完全未写**。

**可用能力**（`tui.d.ts`）：
| 能力 | API | 用途 |
|---|---|---|
| 槽位（常驻 UI） | `api.slots.register({ order, slots })`；`TuiHostSlotMap` = `app` / `app_bottom` / `home_prompt(_right)` / `session_prompt(_right)` / `session_sidebar_(title\|content\|footer)` … | 在界面固定位置渲染（如把「麦克风按钮/指示灯」放到输入框右侧 `session_prompt_right`） |
| 快捷键 | `api.keymap.registerLayer({ commands, bindings })` | 注册热键（如 `ctrl+r` 开始/停止） |
| 路由/会话 | `api.route.navigate(name, params)`、`api.route.current`；`session.get(...)` | **切换会话** |
| 写入输入框 | `api.prompt.set(TuiPromptInfo)` / 事件 `tui.prompt.append` | 把识别结果**填进输入框**（而非直接发送） |
| 提示 | `api.ui.toast(...)` / `api.ui.notify(...)` | 状态提示 |
| 整页路由 | `api.route.register([{name, render}])` | 独立页面（可选） |

**约束与风险**：渲染是 **SolidJS**（`SolidPlugin`）；**无文档、跨版本可能变**；装载需 `exports["./tui"]` 或 `{id, tui}` 导出。

**Web UI / `opencode serve` 不可扩展**（固定 OpenAPI 前端）。

## 3. UI 方案（**已定：A · TUI 槽位**）

- **决定：A（TUI 槽位）**。理由：`/voice` 这类**命令本质是「注入提示词 → 由模型调用工具」**，**有延迟且不可控**（还要等一个模型回合）；要做到「点击即开始/停止、实时状态」必须是**原生 UI**。
- **单插件**：全部落在 `src/tui.tsx`（`export default { id, tui }`）。**不再需要 server 插件**——spike 已证实 TUI 插件自带 `api.client`（`OpencodeClient`），可直接 `session.prompt` 注入、`tui.appendPrompt` 写输入框。
- 形态：
  - 在 **`session_prompt_right`**（输入框右侧）渲染**单个**状态指示 `[🎙状态][注入|输入][F8/F9]`：
    例 `🎙 ●  注入 F8/F9`（麦克风开、注入模式）、`🎙 ⏳ 注入 F8/F9`（启动中）；可变段**定宽填充**（见下），
    故开/关态字形后会有补齐的额外空格（`🎙 ●  注入 …` 有两空格、`🎙 ⏳ 注入 …` 有一空格），总宽仍与「启动中」一致。
    **emoji 后必须留一个空格**，否则 TUI 会因 emoji 显示宽度不同而重叠。
    状态字形：`●`=开 / `○`=关 / `⏳`=启动中；模式名随当前模式切换；第三段恒为 `F8/F9`
    （两个热键都显示，作「可按 `F8`=注入 / `F9`=输入 切换」提示，**不随模式变**）。
    **宽度恒定（定宽填充，2026-10-14）**：状态字形段与模式描述段是**可变段**，其余（`🎙`、`F8/F9`）不变。
    `●`/`○` 在该渲染口径下为 1 列、`⏳` 为 2 列；两语言模式名长度也不同（`注入`/`输入`、`Inject`/`Input`，
    英文最长差 1 列）——直接拼接会随 F8/F9 切换与 mic 状态变化而**整条宽度抖动**。故：
    ① 取状态字形段（字形 + 尾随空格）最大显示宽度 **Wg**（`GLYPH_SEGMENT_WIDTH`，当前 = 3）；
    ② 取**当前语言**下所有模式描述段（名 + 尾随空格）最大宽度 **Wl**（`modeSegmentWidth(phrases)`，
    按 `Phrases` 缓存，同一语言只算一次；zh = 5、en = 7）；
    ③ 两段各自**右侧补空格到 Wg / Wl**，其余段不动 ⇒ 任意 mic 状态 × 模式 × 语言拼接总宽恒定（zh = 16、en = 18）。
    宽度口径与渲染库一致：`@opentui/core` 内联 `string-width@7`（Bun 宿主下为 `Bun.stringWidth`，
    `ambiguousIsNarrow:true`）——歧义宽度字符（`●`/`○`）计 1、emoji（`⏳`/`🎙`）与 CJK 计 2、ASCII 计 1；
    纯函数 `displayWidth`（`src/voice/slot.ts`）复刻同口径并有单测。
    **为何只用一个元素**（2026-10-14）：原先把两个模式各渲染一个指示，占位宽且「哪个是当前」不直观；
    合并为一条后「状态 + 模式 + 热键」一屏可读（渲染函数 `src/voice/slot.ts` `formatSlotIndicator`，纯函数可测）；
    **分段配色**（2026-10-14 追加）：整条指示**按段独立上色**——纯函数 `formatSlotSegments(phrases, { mic, mode, injectOn, inputOn })`
    产出 `{ text, role }` 分段（**不含颜色值**），`src/tui.tsx` 按 `role` 选 `api.theme.current` 的颜色键、逐段 `<text fg>`；
    `formatSlotIndicator` 保留为「分段拼接后的纯文本」（旧调用/单测）。
    **静态结构 + 响应式文本**（2026-10-14）：`src/tui.tsx` 固定渲染 6 个 `<text>` 节点（顺序同分段数组），
    文本/颜色用响应式访问器读取，**不用 `<For>` 逐段重建**——避免分段数组变化时节点被销毁/重建造成的闪烁。配色规则：

    | 段 | `role` | theme 颜色键 | 何时用 |
    |---|---|---|---|
    | `🎙` 图标 | `icon` | `success` / `info` / `textMuted` | 麦克风 开 / 启动中 / 关 |
    | `●` `○` `⏳` 状态字形 | `glyph` | 同图标 | 同上（与图标同色，保留独立角色备微调） |
    | `注入` / `输入` 模式描述 | `mode` | `warning` / `primary` | 注入 / 输入（有激活模式时）；关闭态 `textMuted` |
    | 激活热键（`F8` 或 `F9`） | `keyActive` | 同模式色（`warning` / `primary`） | 对应模式开启时 |
    | 未激活热键 | `keyInactive` | `textMuted` | 始终（未激活的那个键） |
    | `/` 分隔符 | `separator` | `textMuted` | 始终 |

    **关闭态**（无激活模式）：图标/字形用 `textMuted`，模式描述与两个键也都用 `textMuted`（描述仍显示上次模式但整体转暗）；
    颜色键均取自 `TuiThemeCurrent`（`@opencode-ai/plugin` `dist/tui.d.ts` 实证），不使用未定义的键；颜色**只在渲染层**选定，`slot.ts` 只给角色。
  - **两个点按开关热键**（**不能按住**：长按会键重复、且松键不上报，见 spike 结论）：
    - **`F8` = 模式 A「语音注入」**：识别结果经 `client.session.prompt` **变成一条新消息**（带 `🎙` 标记）；
    - **`F9` = 模式 B「语音输入」**：识别结果经 `client.tui.appendPrompt` **增量追加进输入框**，由用户编辑后发送；
    - 两模式互斥；都关闭时停止运行时。
  - 状态用 `api.ui.toast` 反馈；
  - 默认热键已核对：opencode 内置 keybind 仅占用 `f2`（及 `shift+f2`），`F8/F9` 空闲。
- **已否决**：B（外部浮动窗，重）、C（命令，延迟）。
- **风险**：TUI 插件 API **无公开文档 + SolidJS 渲染 + 版本敏感** → 落地前按目标版本核对 `tui.d.ts`；spike 已验证「自定义 TUI 插件能被加载并渲染进槽位 + `api.client` 可调」。

## 4. 全 TS 架构

```
麦克风 ─► [Node 采集] 16k 单声道 PCM 分片
        ─► [Node ASR 客户端] 阿里云实时（WebSocket / 官方 Node SDK）
              └─ 得到 { text, emotion }
        ─► 情绪映射 → emoji(等级/3)
        ─► [opencode TUI 插件] 注入 / 填输入框 / 显示状态
```

### 4.1 麦克风采集（Node）—— **已验通**
- **选定方案**：`ffmpeg-static`（npm 自带预编译 ffmpeg）+ `spawn` 取裸 PCM。
  - 命令：`-f dshow -i audio="<设备名>" -f s16le -ar 16000 -ac 1 -`（Win；mac `avfoundation`、Linux `alsa`）
  - 本机 spike：**采到真实 PCM 帧（非 0）** → 链路成立
- **存储代价**：`ffmpeg.exe` ≈ **79MB** → **不建议随包分发**；改为**运行时按需下载**，或用环境变量 `FFMPEG_BIN` 指定用户自备路径。
- ⚠️ 本机 spike 电平≈静音（RMS≈0.0004）→ 疑似**麦克风被静音/增益 0**，需人工确认真能采到人声。
- 备选：Node 原生音频模块（PortAudio 绑定）——本项目不采用。

### 4.2 ASR（Node）
- **云（阿里云百炼）**：官方有 Node SDK / 或直接 `ws` 实现协议（已有协议细节）：
  - `paraformer-realtime-v2`（无情绪）、`paraformer-realtime-8k-v2`（3 类情绪，仅 8k）、`qwen3-asr-flash-realtime`（7 类情绪，16k）——**推荐 qwen3**（情绪最细）
  - 端点 `wss://{workspaceid}.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference`（或 `/realtime?model=qwen3-asr-flash-realtime`），头 `Authorization: Bearer <apikey>`
- **本地（可选）**：sherpa-onnx 有 Node 绑定（`sherpa-onnx-node`，**需核实**）——有则可保留本地引擎，否则本地引擎暂缓。

### 4.3 情绪 → 标注
- 语音给的是 7 类（happy/sad/angry/fearful/disgusted/surprised/neutral），既有体系是 4 族（怒/疑惑/无语/非常好）×3 级 → **需要映射表**（待定，见 §8）。

### 4.4 注入 / 写输入框（单 TUI 插件，`api.client`）
TUI 插件自带 `api.client`，故**无需 server 插件**。两种模式（互斥，热键切换）：

- **模式 A（语音注入，`F8`）** → 变成新消息，带 `🎙` 标记：
  ```
  api.client.session.prompt({
    sessionID,                       // 取自 api.route.current.params.sessionID
    noReply: false,
    parts: [{ type: "text", text: `🎙 ${annotation ? annotation + " " : ""}${text}` }],
  })
  ```
- **模式 B（语音输入，`F9`）** → 增量追加进主输入框，不覆盖用户已输入内容（spike A 已验证）：
  ```
  api.client.tui.appendPrompt({ text: ` ${annotation ? annotation + " " : ""}${text} ` })
  // 等价备用：api.client.tui.publish({ body: { type: "tui.prompt.append", properties: { text } } })
  ```

> **API 形态注意**：`api.client` 是 **v2** `OpencodeClient`（`@opencode-ai/sdk/v2`），
> 其签名是**扁平的** `session.prompt({ sessionID, parts, noReply })`、`tui.appendPrompt({ text })`；
> 旧的 v1 形态 `{ path: { id }, body: { … } }` 属已删除的 server 插件（`client` 为 v1）。
> 依据：spike 的 `api.client.tui.appendPrompt({ text })`（扁平）实测成功（v1 要求 `{ body: { text } }`）。

- **运行时**：插件 `child_process.spawn` 起 `dist/runtime/voice-runtime.js --json`，逐行读其 stdout 的 NDJSON
  （契约见 `src/voice/ndjson.ts`：`ready` / `final` / `error` / `done`），按当前模式分发。
- **会话 id**：TUI 侧取 `api.route.current`（`{ name:"session", params:{ sessionID } }`）；不在会话路由时提示并忽略。
- 旧方案（2026-10-13 上午）：server 插件在 `127.0.0.1:8799` 起 HTTP 网关、TUI 经 `/start`·`/stop`·`/status` 控制、
> 运行时 POST `/inject`。**已删除**（server 与 TUI 是两个进程，属多余的一跳）。

## 5. 数据流 / 时序（连续对话）
1. 按热键（`F8` 注入 / `F9` 输入）→ 插件 `spawn` `dist/runtime/voice-runtime.js --json`（互斥，仅一个运行时）→ 槽位指示亮起；
2. 运行时 stdout 每行一个 NDJSON 事件 → 插件按行解析；`final` 时按当前模式分发（A 注入 / B 追加）；
3. 再按同键关闭该模式；若两模式都关 → `kill` 子进程、指示熄灭；
4. 子进程异常退出 → 插件复位开关、toast 提示，可按热键重启（不留孤儿进程：`api.lifecycle.onDispose` 会停止它）。

## 6. 关键取舍
| 决策 | 理由 |
|---|---|
| **全 TS** | 部署不依赖 Python |
| **单 TUI 插件**（无 server） | TUI 自带 `api.client`，注入 / 写输入框一步到位；去掉进程间 HTTP 一跳 |
| UI 走 **TUI 槽位**（A） | 原生、无需外部窗口；代价是未公开 API |
| 情绪**统一到 `emoji(等级/3)`** | 与手动来源同一标注，模型好读 |
| 采集用**附 ffmpeg** | Node 原生音频在 Windows 不可靠 |
| 去掉手动符号、留命令 | 语音已自动给情绪，符号冗余 |

## 9. 语音输出（`voice_cli` 工具，server 插件 + CLI）

> 追加（同日）：在「语音输入」之外新增**反向**能力——让模型把文字合成语音并对用户播放。
> 2026-10-14 改版：工具由「`speak` + 内存 provider」改为 **CLI 风格**（`voice_cli` → `voice-cli` 命令），详见 §12。

- **形态**：独立 server 插件 `src/tts-tool.ts`（`export default { id:"tts-tool", server }`），在 `Hooks.tool` 注册**单个**工具 `voice_cli`。
  - **为什么这里必须是 server 插件**：`@opencode-ai/plugin/tui` 的 `TuiPluginModule` 声明 `server?: never`（`tui.d.ts:509`），TUI 插件**不能注册工具**；与 §4.4「注入无需 server 插件」不矛盾——注入走 `api.client`，而**工具**只能由 server 插件提供。
- **provider 抽象** `src/voice/tts/`：
  - `types.ts`：provider 契约 + 配置解析（纯函数，可离线单测）；
  - `emotion.ts`：情绪 → CosyVoice 风格指令映射（纯函数，见 §13）；
  - `sapi.ts`：默认 provider（Windows），`spawn` `pwsh`/`powershell` 执行 System.Speech 脚本；文本走 **base64 环境变量**传入，绝不拼接，中文安全、无注入面；
  - `aliyun.ts`：CosyVoice WebSocket provider；`index.ts`：按名缓存的 provider 注册表 + `speak()` / `stopAll()`。
- **配置**：统一从 `<配置目录>/emotions.jsonc` 读取（`tts.provider` 默认 `sapi`、`tts.voice` 默认空、`tts.rate` 默认 `0`），环境变量 `TTS_PROVIDER`/`TTS_VOICE`/`TTS_RATE` 可覆盖；详见 §10。
- **并发/打断**：provider 单实例、同一时刻至多一个朗读子进程；新 `speak` 先 `stop()` 打断上一条；`dispose` 时 `stopAll()`（见 `docs/ASYNC.md` 交互点 ⑨/⑩）。**注意**：改为 CLI 后，跨进程（多次工具调用）不再互相打断（见 §12.3）。
- **不卡回合**：`execute` 用 `exec` 调 CLI，CLI 的 `speak` 走 `--background`（前台校验后派生分离 `__play` 进程播放），**立即返回**确认。
- **音色可用性**：`pwsh`（PowerShell 7）可选全部 OneCore 音色（Huihui/Kangkang/Yaoyao）；仅 Windows PowerShell 5.1 时只有 Desktop 音色，选不到回落默认音色。
- **产物**：`npm run publish:proj` 把 `dist/` **整体镜像**到 `.opencode/plugin/`（顶层只有 `emotions.js`/`tts-tool.js`/`tui.js`，其余进子目录）；CLI 位于 `dist/cli/voice-cli.js`（镜像后 `.opencode/plugin/cli/`），非插件、不被自动加载（见 §12.1）。
- **provider**：`sapi`（本机 Windows，默认）与 `aliyun`（阿里云 CosyVoice）；不支持当前 provider 的参数会被**忽略并记一条日志**（不报错）。

## 10. 配置化（emotions.jsonc，2026-10-13 追加；2026-10-14 改名，见 changes/）

> 背景：原实现把设备、模型、`language:"zh"`、VAD 写死在代码里；且给 `turn_detection` 传了
> **阿里云不存在的 `prefix_padding_ms`**（无效，已删除）。本节目的是把语音参数全部外置。

## 11. 凭证可配 + ASR 语种/语料 + CosyVoice TTS（2026-10-13 追加）

> 背景：原实现把凭证路径写死在 `voice-runtime.ts`（`<cwd>/.tmp/aliyun`），且 `aliyun` TTS 是空占位。

### 11.1 凭证（`asr.credentials`，`src/voice/credentials.ts`）

- **优先级（逐字段合并）**：
  `DASHSCOPE_API_KEY`/`DASHSCOPE_WORKSPACE_ID`（环境变量） > `asr.credentials.apiKey`/`workspaceId`（配置直填）
  > 凭证文件（1 行 workspaceid / 2 行 apikey） > 默认 `<cwd>/.tmp/aliyun`。
- **文件路径**优先级：CLI `--credentials` > `VOICE_ALIYUN_CREDENTIALS`（兼容 `ALIYUN_CREDENTIALS`）
  > `asr.credentials.path` > 默认路径。
- **安全**：凭证只读、绝不打印；错误文本统一经 `redact()` 脱敏；缺字段抛清晰错误（信息不含密钥）。
- **云 TTS 复用**同一份 `asr.credentials`（同一 DashScope 账号），不新增 `tts.credentials`。

### 11.2 ASR 语种/语料（`src/voice/config.ts` `resolveAsrParams` + `src/voice/aliyun.ts` `buildRunTask`）

- `asr.languageHints`（list）→ paraformer `parameters.language_hints`（显式优先，否则由 `asr.language` 推导）；
  仅 `aliyun-8k`/`aliyun-v2` 支持。
- `asr.vocabularyId` → paraformer `parameters.vocabulary_id`（热词表须先经 VocabularyService 预建、`target_model` 一致）；
  仅 `aliyun-8k`/`aliyun-v2` 支持。
- `asr.context` → inference `input.context`（领域语料）；**当前无 provider 支持**。
  - 依据：官方「提升识别准确率」支持列表**不含** `qwen3-asr-flash-realtime`（该模型无热词/上下文增强参数）；
    paraformer 系列只有 `vocabulary_id` 热词、无 `context`。故 `qwen3-asr-flash-realtime` 传热词/上下文/语言提示
    一律**忽略并记日志**（不报错）。
- 过滤逻辑为纯函数 `resolveAsrParams(preset, requested) → {…, ignored[]}`，有参数桩单测。

### 11.3 CosyVoice TTS provider（`src/voice/tts/aliyun.ts`）

- **接入方式**（官方当前推荐）：WebSocket `run-task` 协议，
  端点 `wss://{workspace}.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference`
  （通用域名 `dashscope.aliyuncs.com` 仍可用，专属域名官方建议迁移）；
  握手头 `Authorization: Bearer <apiKey>` + `X-DashScope-WorkSpace: <workspace>`。
  流程：`run-task`(input{}) → 收 `task-started` → `continue-task`(正文) → `finish-task` → 收二进制音频帧 → `task-finished`。
- **参数**（`payload.parameters`）：`text_type:"PlainText"`、`voice`、`format`(pcm/wav/mp3/opus)、
  `sample_rate`(8000/16000/22050/24000/44100/48000)、`volume`(0-100)、`rate`(0.5-2)、`pitch`(0.5-2)、
  `instruction`（方言/情感/角色，≤100 字）。
- **模型**：默认 `cosyvoice-v2`（`tts.model` 可覆盖）；系统音色默认 `longxiaochun_v2`（`tts.voice` 可覆盖）。
  - ⚠️ **模型与音色版本必须一致**：v2 模型只能用 v2 音色、v3 只能用 v3 音色，混用会返回
    `Engine return error code: 418`（如 `longanyang` 属 v3-flash/v3-plus，配 `cosyvoice-v2` 即 418）。
    本次自测已复现并据此把默认音色从误用的 `longanyang` 改为 v2 的 `longxiaochun_v2`。
- **播放**：合成结果落临时 WAV（非 wav 用 ffmpeg 转码），用 PowerShell `System.Media.SoundPlayer` 同步播放；
  播放进程可被新 `speak`/`dispose` 打断。**播放仅 Windows**（非 Windows 抛清晰错误）。
  - ⚠️ **流式 WAV 头陷阱（2026-10-14 修）**：CosyVoice 返回的 `format=wav` 是**流式 WAV**，其 RIFF 总长与 `data`
    块长度是占位值（约 `0x7fffffxx` ≈ 2GB）。`System.Media.SoundPlayer` 对此**不报错**，而是按占位长度读到即时 EOF →
    **静默不出声**（实测同一段 0.68s 音频：原样头 `PlaySync` 仅阻塞 11ms，修正头后 784ms，基线正弦 756ms）。
    故落盘前统一经 `normalizeWavHeader()`（`src/voice/tts/aliyun.ts`）按实际字节数重写两处长度；该函数对正常 WAV 幂等。
  - 另：合成返回 0 字节 → 直接抛错（不静默）；播放子进程**非 0 退出码**记 `error` 日志（此前仅忽略）。
- **`qwen3-tts-flash`（HTTP）**：仅 `voice`/`language_type`，无风格/语速 → 本轮不接入（`qwen-audio-3.x-tts` 情感靠文本内嵌标签）。
- **并发契约**：见 `docs/ASYNC.md` 交互点 ⑩。

### 11.4 忽略不支持参数

- ASR：`resolveAsrParams` 过滤，`voice-runtime` 对 `ignored` 记一条 stderr 日志（logger 无 debug 级别）。
- TTS：`ignoredTtsParams(provider, options)` 过滤，`tts/index.ts` 记一条日志；如 sapi 收到 `instruction`/`pitch`/… 只忽略不报错。

## 12. 语音 CLI（`voice_cli` 工具 + `voice-cli` 命令，2026-10-14）

> 背景：原 `speak` 工具把入参直接喂给内存里的 provider；改为 **CLI 风格**（照本机 `stats-command.js` 模式），
> 让「工具」与「命令行」共用同一入口，且模型只需给一条参数串。

### 12.1 工具契约（`voice_cli`）

- 注册**单个**工具 `voice_cli`（`src/tts-tool.ts`），参数只有一个可选字符串 `args`；`execute` 把 `args` 拼成
  `node <cli> <args>` 用 `exec` 运行（`windowsHide: true`、`maxBuffer` 64MB），返回 `{ title, output }`。
- 未给 `args` → 视作 `help`；`speak` 自动补 `--background`（保持「不卡回合」）。
- 兜底：先试 PATH 上的 `node`，失败再用 `process.execPath`（Bun 宿主下即 bun）。
- CLI 路径解析：`VOICE_CLI_SCRIPT`（存在则用）> `<cwd>/dist/cli/voice-cli.js` > 由插件位置上溯的 `<仓库根>/dist/cli/voice-cli.js`。CLI 位于**子目录** `dist/cli/`（镜像后 `.opencode/plugin/cli/`）：opencode 只自动 import `.opencode/plugin/` **顶层**的 `.js`，子目录不被扫描，故 CLI 启动时不会被误当插件执行。
- **入口保护**：`src/cli/voice-cli.ts` 顶层只在 `isDirectEntry()`（`realpath(process.argv[1]) === realpath(本模块)`）为真时执行 `main()`；被 import 时无副作用、不打印（`main`/`isDirectEntry` 导出供单测）。回归测试见 `test/voice-cli.test.js`「voice-cli 入口保护」。

### 12.2 CLI 子命令（`src/cli/voice-cli.ts` → `dist/cli/voice-cli.js`）

| 子命令 | 说明 |
|---|---|
| `speak --text <t> [--emotion <e>] [--voice <v>] [--rate <n>] [--provider <p>] [--background]` | 合成并播放；`--background` 立即返回（后台播放） |
| `devices` | 列出本机音频输入设备（ffmpeg dshow） |
| `status` | 打印解析后的配置（语言/provider/音色/语速/指令/凭证是否存在；**绝不打印密钥**） |
| `help` | 用法（随 `language` 本地化） |
| `__play`（内部） | 由 `speak --background` 以分离进程调用，前台执行真正的合成+播放 |

- 参数解析为纯函数 `src/voice/cli.ts` `parseCliArgs`（支持 `--flag value` / `--flag=value`、短名 `-t/-e/-v/-r/-p`；负数字面量可作取值）。
- **进程模型**：`speak --background` 在前台完成 **provider 名与云凭证校验** 后，`spawn(detached, stdio:"ignore").unref()`
  派生 `__play`（参数经环境变量 `OC_VOICE_PLAY` base64 传递，不落命令行、不含密钥）；前台打印确认即退出。
  `__play` 靠子进程/WebSocket 句柄自然存活到播放结束。

### 12.3 已知限制（CLI 化的代价）

- **跨进程不保证打断**：同一次进程内 `speak()` 会先 `stop()` 上一条，但工具每次调用各派生独立 `__play`，两条并发朗读不会互相打断。
- **dispose 不再 stop**：分离播放进程无跨进程句柄，opencode 退出不会主动停止正在播放的语音（正常播完会自行退出）。
- 单机同一时刻的 provider 实例只在**单个 `__play` 进程内**唯一。

## 13. 情绪风格与多语言（i18n，2026-10-14）

### 13.1 情绪 → CosyVoice 风格指令（`src/voice/tts/emotion.ts`）

- `speak --emotion <name>` / 工具参数串里的 `--emotion`；映射为 CosyVoice `instruction`（中文风格指令，≤100 字）。
- sapi **无风格能力**：由 `ignoredTtsParams` 判为忽略（只记一条日志，不报错）。
- 指令文本**固定中文**（CosyVoice v2 是中文模型；与 UI 的 `language` 无关）。
- 规范情绪与别名（大小写/空白不敏感；**别名 → 规范名**）：

  | 规范名 | instruction | 别名 |
  |---|---|---|
  | `happy` | 用开心的语气说 | `great` `excited` `joyful` `glad` `good` `nice` `ok` `okay` `fine` |
  | `sad` | 用悲伤的语气说 | — |
  | `angry` | 用愤怒的语气说 | `anger`(族名) `annoyed` `mad` `furious` `rage` |
  | `fearful` | 用恐惧的语气说 | `fear` `afraid` |
  | `disgusted` | 用厌恶的语气说 | `disgust` |
  | `surprised` | 用惊讶的语气说 | `surprise` `astonished` |
  | `confused` | 用疑惑的语气说 | `confusion`(族名) `puzzled` |
  | `speechless` | 用无奈的语气说 | `sigh` `meh` `helpless` |
  | `neutral` | （不加指令） | `calm` `plain` |

- 覆盖优先级：`--emotion` 解析出的指令 > `TTS_INSTRUCTION` 环境变量 > `tts.instruction` 文件配置 > 空。
  `neutral`/空值/未知情绪 → 空指令，于是**回退**到 env/文件配置。
- 复用既有情绪族英文名（`anger`/`confusion`/`speechless`/`great`）作为别名，与 §4.3 的语音情绪标注体系统一。

### 13.2 多语言（`src/lib/i18n.ts`）

- 配置键 **`language`**（`zh` 默认 / `en`；环境变量 `VOICE_LANGUAGE`）；`resolveLanguage()` 大小写/区域不敏感（`zh-CN`→`zh`、`EN`→`en`），非法值回退 `zh`。
- **覆盖范围**：① server 插件**加载时**本地化工具描述（`voice_cli` 的 `description` 与 `args` 说明）；② TUI 槽位指示、toast、命令标题；③ `voice-cli --help`。
- **词表集中**在 `src/lib/i18n.ts` 的 `PHRASES`（`zh`/`en` 各一份 `Phrases`，键由类型强制对齐），带变量文案用 `{name}` + `format()`；禁止在调用处散落硬编码。
- 新增语言：在 `LANGUAGES` 与 `PHRASES` 各加一项即可（类型会要求补齐全部键）。
